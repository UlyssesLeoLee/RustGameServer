## 2. 已实施分区

### 2.1 `realm_lifecycle_run` (admin_db) — 已按月分区

**出处**：`crates/cluster-ops/migrations/0020_lcm_tables.sql:47` + DO 块 line 51-67

```sql
CREATE TABLE IF NOT EXISTS realm_lifecycle_run (
    ...
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    ...
) PARTITION BY RANGE (created_at);

-- 初始分区：当月 + 下月（per DO 块）
DO $$
DECLARE
    current_month_start TIMESTAMPTZ := date_trunc('month', now());
    next_month_start TIMESTAMPTZ := date_trunc('month', now()) + INTERVAL '1 month';
    month_after_start TIMESTAMPTZ := date_trunc('month', now()) + INTERVAL '2 month';
    current_partition TEXT := 'realm_lifecycle_run_y' || to_char(current_month_start, 'YYYYMM');
    next_partition TEXT := 'realm_lifecycle_run_y' || to_char(next_month_start, 'YYYYMM');
BEGIN
    EXECUTE format(
        'CREATE TABLE IF NOT EXISTS %I PARTITION OF realm_lifecycle_run FOR VALUES FROM (%L) TO (%L)',
        current_partition, current_month_start, next_month_start
    );
    EXECUTE format(
        'CREATE TABLE IF NOT EXISTS %I PARTITION OF realm_lifecycle_run FOR VALUES FROM (%L) TO (%L)',
        next_partition, next_month_start, month_after_start
    );
END $$;
```

**评估**：
- ✅ 完整 RANGE 分区 + DO 块自动建初始分区
- ⚠️ 缺生产环境分区滚动 cron job（**PH-2 评审**）
- ⚠️ 缺 DETACH/DROP 过期分区脚本（**PH-2 评审**）

## 3. 应实施但未分区（识别为不合理设计）

### 3.1 `audit_log` (admin_db) — 应按月分区（P0-02）

**现状**：未分区，亿级行/年增长。

**问题**：
- 3 年保留期意味着 ~1.8 亿行（全在单表）
- 索引膨胀，查询性能劣化
- 备份/恢复成本随数据量线性增长

**建议**：
- 按 `created_at` 月度范围分区
- 3 年保留期（36 个分区滚动）
- 应用 ARC-014 "未证明前不引入复杂性" → 但 audit_log 已被 RGS-BAS-007 §4 明确要求分区
- 优先级 **P0**（影响合规 + 性能）

详见 [17-不合理设计 P0-02](17-不合理设计识别与优化建议.md)。

### 3.2 `outbox` × 6 域 — 应按周/月分区（P0-03）

**现状**：未分区，6 域每域千万级/日增长。

**问题**：
- 总量 = 6 × 千万 × 365 ≈ 数十亿/年
- `idx_outbox_pending` / `idx_outbox_in_flight` 索引膨胀
- `status='sent'` 历史数据无法快速清理

**建议**：
- 按 `created_at` 周/月范围分区（依各域吞吐量）
- 已发布（`status='sent'`）的记录短期归档后清理
- 优先级 **P0**（影响 6 域 worker 性能）

详见 [17-不合理设计 P0-03](17-不合理设计识别与优化建议.md)。

### 3.3 `inbox` (economy_db) — 应按时间分区（P2-01）

**现状**：未分区，幂等记录短保留期。

**问题**：
- 处理过的 command 永久保留——按设计应该是 7 天重试窗口后清理
- 数据量会无限增长

**建议**：
- 按 `processed_at` 月度分区
- 30 天保留期
- 优先级 **P2**（影响小，可后置）

### 3.4 `reservations` (economy_db) — 应按时间分区（P2-02）

**现状**：未分区，saga 资金预留。

**问题**：
- 7 天 expired 清理但 DB 层无强保证
- 数据量随 saga 启动频率线性增长

**建议**：
- 按 `created_at` 月度分区
- 7 天保留期
- 优先级 **P2**

### 3.5 `moves` (match_db) — 应按时间分区（P1-07）

**现状**：未分区，卡牌对战操作日志。

**问题**：
- 亿级/年增长
- 老对局的 moves 几乎不会被查询（除 GM 调查）

**建议**：
- 按 `occurred_at` 月度分区
- 1 年保留期（per 业务）
- 优先级 **P1**

详见 [17-不合理设计 P1-07](17-不合理设计识别与优化建议.md)。

### 3.6 `replays` (replay_db) — 应按时间分区（P1-15）

**现状**：未分区，元数据表。

**建议**：
- 按 `expires_at` 月度分区（与 TTL 清理同步）
- 优先级 **P1**

详见 [17-不合理设计 P1-15](17-不合理设计识别与优化建议.md)。

## 5. 分区滚动 SOP（生产环境 cron job）

> PH-2 评审后实施。

```sql
-- 月度分区滚动（每月 1 号 UTC 0:00 跑）
-- 1. 创建下下月分区（确保写入有目标）
DO $$
DECLARE
    target_month_start TIMESTAMPTZ := date_trunc('month', now()) + INTERVAL '2 month';
    month_after_start TIMESTAMPTZ := date_trunc('month', now()) + INTERVAL '3 month';
    target_partition TEXT := 'realm_lifecycle_run_y' || to_char(target_month_start, 'YYYYMM');
BEGIN
    EXECUTE format(
        'CREATE TABLE IF NOT EXISTS %I PARTITION OF realm_lifecycle_run FOR VALUES FROM (%L) TO (%L)',
        target_partition, target_month_start, month_after_start
    );
END $$;

-- 2. DETACH 过期分区（保留 3 年 = 36 个月前的）
DO $$
DECLARE
    expired_month_start TIMESTAMPTZ := date_trunc('month', now()) - INTERVAL '37 month';
    expired_partition TEXT := 'realm_lifecycle_run_y' || to_char(expired_month_start, 'YYYYMM');
BEGIN
    -- 先归档到冷存储（对象存储）再 DROP
    -- 实际实现：pg_dump 该分区 → 上传 S3 → DROP
    EXECUTE format('ALTER TABLE realm_lifecycle_run DETACH PARTITION %I', expired_partition);
    EXECUTE format('DROP TABLE %I', expired_partition);
END $$;
```

## 6. SQLite 不支持分区

`resume_tokens` (SQLite) **不支持** PG 声明式分区——SQLite 仅支持表级清理。应用层定时 job 跑 `DELETE FROM resume_tokens WHERE expires_at < now()` 即可（已用 `idx_resume_tokens_expires_at` 索引加速）。
