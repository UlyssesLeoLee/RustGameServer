## 0. 调查方法

**关键发现** — 之前用文件名编号配对是错的:**RGS-REQ-NNN 与 RGS-BAS-NNN 的 NNN 不一一对应**(BAS 编号连续,REQ 编号含附件 addendum 等)。正确配对方法 = 读 BAS 头部"父文档"行,反向索引到 REQ。

```python
# scripts/reqbas_audit.py（提议落地后实现为 CI 工具）
import glob, re
for bas in glob.glob("docs/**/RGS-BAS-*.md", recursive=True):
    parent = re.search(r"\| 父文档 \| ([^|]+)\|", open(bas).read()).group(1)
    reqnum = re.search(r"RGS-REQ-(\d+)", parent).group(1)
    # 配对到 reqs[reqnum]
```

## 2. 调查的 6 个关键发现

### 2.1 BAS 编号 ≠ REQ 编号

BAS 编号连续(001-037 + 100),REQ 编号含附件(002/003/004/005) + addendum(007/025/028/030/031) + 100 + 38(2026-08-25 新增)。机械按编号配对 = 误判 6 份(BAS-001/002/003/004/005/014 都被错配)。**正确配对 = BAS 父文档行反向索引**。

### 2.2 BAS 普遍超前于 REQ 是正常

RGS 文档结构是"REQ 是纲要 + 实施约束,BAS 是实现细化",BAS_LEAD 25/35 = 71% 是正常状态(意味着 BAS 实施时已经先于 REQ 决策完成)。

### 2.3 BAS-001 / BAS-010 表面滞后实则不需同步

- **BAS-001 v1.4 (8-25)** 与 **REQ-001 v1.5 (8-25)** 同日升版。BAS-001 v1.4 反映 ADR-0057;REQ-001 v1.5 反映 §14.2 登记 ARC-047。两者内容不交叉。BAS-001 父 REQ-001 §10 章,无 §14.2 引用需求。
- **BAS-010 v0.4 (8-17)** 反映双态 OLU 模式;REQ-001 v1.5 (8-25) 仅 §14.2 登记 ARC-047。BAS-010 父 REQ-001 §10 章,无 §14.2 引用需求。

### 2.4 REQ-028/029/030 "无 BAS" 是脚本误判

脚本按 REQ-001〜037 编号范围查 BAS,实际 BAS-025/026/027 是它们的对应 BAS(已存在,REQBAS 同日升版)。**REQ-028/029/030 不缺 BAS**。

### 2.5 REQ-002/003/004/005 是基准附件,本身无需基本设计

REQ-002 = 附件A 术语表、REQ-003 = 附件B NFR 等级、REQ-004 = 附件C 可追溯性矩阵、REQ-005 = 附件D 风险管理表。这 4 份是"元文档",不需 BAS。

### 2.6 REQ-038 (8-25 新增) 真正需要新建对应 BAS

- 父文档:无对应 BAS
- 涉及:核心传输防丢包强化与周边协议选型(ARC-047)
- 状态:刚 v0.1 起草
- Mavis 建议:待 REQ-038 升 v0.2(锚定状态)后再建对应 BAS;**v0.1 阶段不必新建**(BAS 配 REQ 锚定态是基线规范)
