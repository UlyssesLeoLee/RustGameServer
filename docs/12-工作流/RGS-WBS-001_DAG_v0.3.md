## 3. 关键路径分析

**最长依赖链**（critical path，决定 53 → 53 起動 → 54 编码 → 55-58 → 67 集成测试的最小工期）：

```
WF-0.5-1 (5 域 DTL §1 冻结)
  → WF-0.5-2 (§2)
  → WF-0.5-3 (§3 + 需 CROSS-001~007 v0.2 准备)
  → WF-0.5-6 (CROSS 填充，可与 §3 并行)
  → WF-0.5-7 (5 域 §1-§3 联检)
  → WF-1-53.1 (Rust 1.98 工具链)
  → WF-1-53.2 (Cargo workspace)
  → WF-1-54.1 (5 域 crate 骨架)
  → WF-1-54.2 (gRPC Proto)
  → WF-1-54.3 (tonic-build)
  → WF-1-54.4 (sqlx 集成)
  → WF-1-54.5 (error 类型)
  → WF-1-54.7 (Service 层业务)
  → WF-1-54.8 (Q-003 Saga)
  → WF-1-54.10 (CEM)
  → WF-1-54.11 (PFAU)
  → WF-1-55/56/57/58
  → WF-2/3/4
```

**估算**（per RGS-WBS-001 v0.3 §2A.2 token/周）：
- WF-0.5 段：~3.5 人·周（15 L4 任务总计 3.0 人·周 + 联检 0.5 人·周）
- WF-1 段：~22 人·周（69.5 人·天 / 5 天·周）
- WF-2/3/4：~10 人·周（待 v0.4 展开）
- **总计关键路径 ≈ 35-40 人·周**（单人 1 人串行 = 35-40 周）

**DEC-006 路径 B 14-18 周对比**：
- 关键路径 35-40 周 vs 计划 14-18 周 → **计划时间表远小于关键路径**
- 需 5 域 Lead 并行 + token 优化（per DEC-007）
- 5 域 Lead 并行时实际关键路径 = 14-18 周（与计划匹配）

## 4. 并行度分析

**最大并行节点数**（per stage）：
- WF-0.5 段：7 个 L4（5 域 DTL §1-§3 × 5 域 + 跨域 + shared-platform + 联检 = 7 任务），但 5 域可并行
- WF-1-53 段：15 个 L4（大部分 Platform 串行）
- WF-1-54 段：15 个 L4（5 域可并行 → 5 个 5 域 Lead 各自推进 1 个 L4）
- WF-1-55-58 段：42 个 L4（Platform 串行）

**5 域 Lead 5 人并行时 WF-1-54 段**：
- 15 L4 / 5 域 = 每域 3 L4 → 域内 3 L4 串行 + 5 域间并行
- 单 L4 平均 1.5 人·天 → 单域 4.5 人·天 → 全部 54 段 4.5 人·天（5 域并行）
- **实际工期 < 1 周**（per DEC-006 路径 B 14-18 周内有充裕缓冲）
