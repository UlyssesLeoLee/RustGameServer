# 1. 背景与范围

## 1.1 背景

`crates/replay-extra-service/` 是 RGS 7 域扩展（per 路线图 §3 W5 + 9/4 MD §2）下独立拆分的录像扩展微服务。其设计**承接** replay-service 既有的录像存储核心能力，但承担**录像扩展**功能：录像元数据 / 录像分享 / 录像点赞 / 录像评论 / 录像举报等。

本域覆盖 1 个 gRPC service（ReplayExtraService）、10 个 RPC（含 1 HealthCheck）。其中 8 RPC 为真实业务逻辑（录像元数据 / 分享 / 互动 / 收藏），2 RPC 为 Unimplemented stub。

## 1.2 范围边界

**In-Scope**：
- 录像元数据管理（标题、描述、标签、可见性）
- 录像分享（链接生成、密码保护）
- 录像互动（点赞、评论、举报）
- 录像收藏

**Out-of-Scope**：
- 录像文件存储底层（属 replay-service 既有职责）
- 录像生成（由 battle-service 等上游触发）
- 录像回放渲染（属客户端范畴）

## 1.3 与既有基础设施的关系

| 既有机制 | 本域使用方式 |
|---|---|
| replay-service 既有 | 录像文件存储**严格**复用既有 |
| ARC-008 5 独立 DB → 7 域扩展 | 落位独立 `replay_extra_db`（仅元数据/互动） |
| RGS-REQ-016 §4 反作弊 / 举报 | 录像举报经既有举报系统（per RGS-BAS-025） |

# 3. 业务需求 (BR)

## BR-RPL-001 录像元数据管理

- 录像上传后**必须**支持元数据编辑（标题 / 描述 / 标签 / 可见性）
- 可见性枚举：私有 / 好友可见 / 公开

**验收**：元数据可 CRUD + 可见性可切换。

## BR-RPL-002 录像分享

- 玩家可生成录像分享链接（per 可见性）
- 玩家可对私有录像设置密码保护
- 链接有效期（per ShareConfig）

**验收**：分享链接可生成 + 校验密码 + 过期回收。

## BR-RPL-003 录像互动

- 点赞（每录像每玩家至多 1 次）
- 评论（每录像每玩家至多 N 条）
- 举报（经既有 RGS-BAS-025 反作弊体系）

**验收**：3 类互动均能 CRUD。

## BR-RPL-004 录像收藏

- 玩家可收藏他人录像
- 收藏夹分类（按游戏模式 / 玩家 / 自定义）

**验收**：收藏可 CRUD + 分类。

# 4. 功能需求 (FR)

## 4.1 元数据管理

| ID | 需求 |
|---|---|
| FR-RPL-001 | ReplayExtraService `UpdateMetadata` **必须**支持标题/描述/标签/可见性 4 字段更新 |
| FR-RPL-002 | 可见性变更**必须**触发既有举报系统重新评估（per RGS-BAS-025 §3） |

## 4.2 分享

| ID | 需求 |
|---|---|
| FR-RPL-010 | `GenerateShareLink` **必须**返回 token + 过期时间 |
| FR-RPL-011 | 私有录像**应当**支持密码保护（per ShareConfig.require_password） |
| FR-RPL-012 | 链接过期**必须**自动失效 |

## 4.3 互动

| ID | 需求 |
|---|---|
| FR-RPL-020 | `Like` **必须**每录像每玩家至多 1 次（UNIQUE 约束） |
| FR-RPL-021 | `Comment` **必须**限频（每录像每玩家至多 N 条 / 24h） |
| FR-RPL-022 | `Report` **必须**经既有 RGS-BAS-025 反作弊举报通道 |

## 4.4 收藏

| ID | 需求 |
|---|---|
| FR-RPL-030 | `Favorite` **必须**支持自定义收藏夹分类 |
| FR-RPL-031 | 收藏夹**应当**有上限（per FavoriteConfig.max_count） |

# 5. 非功能需求 (NFR)

| ID | 类别 | 内容 | 目标值 / 判定基准 |
|---|---|---|---|
| NFR-RPL-001 | 性能 | 元数据查询 P99 | < 100ms |
| NFR-RPL-002 | 一致性 | 互动 / 收藏**必须**与录像文件状态同步（录像删除 → 互动失效） | per RGS-DTL-001 §3.2 |

# 6. 架构设计方针 ARC-051

## 6.1 ARC-051：录像扩展 + 复用 replay-service 既有存储原则

| 项目 | 内容 |
|---|---|
| **决定** | 录像扩展域仅承担"录像元数据 / 分享 / 互动 / 收藏"等扩展功能；录像文件存储**严格**复用 replay-service 既有 |
| **理由** | 录像文件存储 vs 录像扩展是两类不同范畴：前者是基础设施（CDN/对象存储），后者是业务功能（互动/分享）。两者分离避免域职责混淆 |
| **数据驱动配置的承载机制** | ①可见性规则 / 密码规则 / 收藏上限作为 ARC-021 既有插件通道承载 |
| **否决方案** | "在 replay-extra 内自建录像文件存储"——直接违反既有 replay-service 职责，已否决 |
| **适用范围** | 本域所有录像扩展功能（元数据 / 分享 / 互动 / 收藏） |
