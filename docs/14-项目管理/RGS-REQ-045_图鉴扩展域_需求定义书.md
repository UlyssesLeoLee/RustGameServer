# 1. 背景与范围

## 1.1 背景

`crates/leaderboard-extra-service/` 是 RGS 7 域扩展下独立拆分的图鉴扩展微服务。其设计**承接** leaderboard-service 既有的排行榜核心能力，但承担**图鉴扩展**功能：成就系统 / 收藏册 / 称号系统 / 解锁进度等。

本域覆盖 1 个 gRPC service（LeaderboardExtraService）、7 个 RPC（含 1 HealthCheck）。其中 5 RPC 为真实业务逻辑（成就 / 收藏 / 称号），2 RPC 为 Unimplemented stub。

## 1.2 范围边界

**In-Scope**：

- 成就系统（解锁 / 进度 / 奖励）
- 收藏册（卡牌 / 道具 / NPC 等）
- 称号系统（获得 / 佩戴 / 展示）
- 解锁进度（按账号聚合）

**Out-of-Scope**：

- 排行榜核心（属 leaderboard-service 既有）
- 排行榜派生视图（属 GSM 既有）
- 卡牌数值平衡（属策划层）

## 1.3 与既有基础设施的关系

| 既有机制 | 本域使用方式 |
|---|---|
| leaderboard-service 既有 | 排行榜核心**严格**复用既有 |
| ARC-008 5 独立 DB → 7 域扩展 | 落位独立 `leaderboard_extra_db`（仅成就/收藏/称号） |
| RGS-REQ-013 FR-GOV-001 | 成就奖励经 EC 单点 |

# 2. 术语约定

| 术语 | 英文 | 含义 |
|---|---|
| 成就 | Achievement | 解锁即奖励，含进度（如累计登录 N 天） |
| 收藏册 | Collection | 卡牌 / 道具 / NPC 的完整收藏 |
| 称号 | Title | 获得后可佩戴，显示在玩家名旁 |
| 解锁进度 | UnlockProgress | 玩家对所有成就 / 收藏的解锁百分比 |

# 3. 业务需求 (BR)

## BR-LBX-001 成就系统

- 成就分类（剧情 / 战斗 / 社交 / 收藏 / 活动）
- 成就解锁：触发条件 + 进度跟踪 + 奖励发放（经 EC 单点）
- 成就展示：已解锁 / 未解锁 + 进度条

**验收**：成就可解锁 + 进度跟踪 + 奖励发放 + 展示。

## BR-LBX-002 收藏册

- 收藏分类（卡牌 / 道具 / NPC / 装备）
- 收藏进度：已拥有 / 总数
- 收藏奖励：完成度 25% / 50% / 75% / 100% 触发奖励

**验收**：收藏可 CRUD + 进度查询 + 阶段性奖励。

## BR-LBX-003 称号系统

- 称号获得：成就解锁 / 收藏完成 / 活动奖励
- 称号佩戴：玩家可佩戴 1 个称号
- 称号展示：玩家档案 / 战斗界面 / 聊天界面

**验收**：称号可获得 + 佩戴 + 展示。

## BR-LBX-004 解锁进度

- 玩家全局解锁进度（成就 + 收藏）
- 服务端聚合（per PlayerId）

**验收**：解锁进度可查询。

# 4. 功能需求 (FR)

## 4.1 成就系统

| ID | 需求 |
|---|---|
| FR-LBX-001 | `UnlockAchievement` **必须**支持 5 类（剧情/战斗/社交/收藏/活动） |
| FR-LBX-002 | 进度跟踪**必须**支持累计型（如累计登录）+ 阈值型（如一次性完成 X 任务） |
| FR-LBX-003 | 成就奖励**必须**经 EC 单点（per FR-GOV-001） |

## 4.2 收藏册

| ID | 需求 |
|---|---|
| FR-LBX-010 | `AddToCollection` **必须**支持 4 类（卡牌/道具/NPC/装备） |
| FR-LBX-011 | 收藏进度**必须**支持 25% / 50% / 75% / 100% 阶段性奖励 |
| FR-LBX-012 | 阶段性奖励**必须**经 EC 单点 |

## 4.3 称号系统

| ID | 需求 |
|---|---|

| FR-LBX-022 | 称号展示**应当**走客户端 UI（不在本域 RPC 范围） |

| ID | 需求 |

# 6. 架构设计方针 ARC-053

## 6.1 ARC-053：图鉴扩展 + 复用 leaderboard-service 既有原则

| 项目 | 内容 |
|---|---|
| **决定** | 图鉴扩展域仅承担"成就 / 收藏册 / 称号 / 解锁进度"4 类扩展功能；排行榜核心**严格**复用 leaderboard-service 既有 |
| **理由** | 排行榜是高频读路径（每场战斗结束 / 玩家打开面板均查），图鉴是低频读路径（成就 / 收藏 / 称号改动频率低）。两者分离避免 leaderboard 主路径受图鉴写影响 |
| **承载机制** | 成就规则 / 收藏册分类 / 称号规则作为 ARC-021 既有插件通道承载 |
| **否决方案** | "在 leaderboard-extra 内自建排行榜核心"——直接违反既有职责，已否决 |
| **适用范围** | 本域所有图鉴扩展功能 |
