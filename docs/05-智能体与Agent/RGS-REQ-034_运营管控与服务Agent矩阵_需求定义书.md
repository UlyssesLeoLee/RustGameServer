| **BR-AGO-001** | SRE 全天候自愈与告警降噪 | 压降 80% 重复无效报警，自动定位根因并执行安全的节点隔离自愈 | PH-2 |

## 2. 功能需求（FR）

| 需求编号 | 需求名称 | 详细说明 | 优先级 |
|---|---|---|:---:|
| **FR-AGO-001** | 告警聚类与拓扑 RCA 定位 | 结合 K8s 拓扑与调用链，将海量关联报警自动聚合为单一根因报告 | ◎ |
| **FR-AGO-002** | Quarantine 隔离池自治调度 | PFAU 升级或节点异常时，自动向 L0 闸门提交摘除路由指令，保障大盘不卡死 | ◎ |
| **FR-AGO-003** | 全链路订单流水双向对账 | 对比第三方支付回调、Outbox 表与 Ledger 账本，定位充值不到账根因 | ◎ |
| **FR-AGO-004** | 玩家情绪感知与满意度自适应 | 实时识别工单中玩家负面情绪，自适应调整回复语气并提高处理优先级 | ○ |
| **FR-AGO-005** | 作弊行为画像与证据链打包 | 聚合异常速度、视野穿透与行为熵值，自动生成带 TraceID 与录像片段的封禁提报单 | ◎ |

## 3. 非功能需求（NFR）

| 编号 | 区分 | 指标要求 |
|---|---|---|
| **NFR-AGO-001** | 安全执行 | Agent 不拥有业务写权限；所有隔离、补偿、封禁等写意图必须 100% 经 L0 Action Gate 的身份、签名、授权、配额、时效与重放校验，任一校验失败即拒绝执行。 |
| **NFR-AGO-002** | 审计与可追溯性 | 每个被提交的写意图和其最终回执必须关联 `intent_id`、`trace_id`、证据摘要、策略/模型版本与审批或拒绝原因；审计留存遵循既有安全与合规策略。 |
| **NFR-AGO-003** | 安全降级 | Agent、模型网关或依赖的观测数据不可用时，系统必须 fail closed：不自动执行待处理意图，转人工工单或告警，核心游戏与账本写路径不受 Agent 故障影响。 |

## 4. 架构方针（ARC-055，提案，待具名人类审批）

**“运营 Agent 只生成建议或 `ActionIntent`；L0 Action Gate 才是唯一执行者。”**

本方针尚未构成已批准架构决定。其落地前，必须由架构、安全、SRE 与项目负责人完成具名评审，并登记 ADR、OLU 与风险处置结果。任何 Agent 直连业务写接口的实现均不在本需求范围内。

## 5. 验收标准（AC）

| 验收编号 | 通过标准 | 关联需求 |
|---|---|---|
| **AC-AGO-001** | 伪造签名、过期意图、重复 nonce 或重复订单均被 L0 闸门拒绝，并产生可检索审计回执。 | FR-AGO-002/003、NFR-AGO-001/002 |
| **AC-AGO-002** | 告警风暴只能产生可审计的根因建议或受控隔离意图；缺少有效闸门许可时不得改变路由或节点状态。 | FR-AGO-001/002、NFR-AGO-001/003 |
| **AC-AGO-003** | 补偿意图必须以权威订单/账本状态、当前配额和幂等键复核为准；任一依赖不可用时转人工而非自动补偿。 | FR-AGO-003、NFR-AGO-001/003 |
| **AC-AGO-004** | 风控/客服输出可关联到 `trace_id`、证据摘要与最终处置状态，且不泄露超出既有授权范围的数据。 | FR-AGO-004/005、NFR-AGO-002 |
