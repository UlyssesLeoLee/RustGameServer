## 1. 前言与业务背景

随着 `RustGameServer` 集群规模扩展至 5 域全开架构（Player/Economy/Match/Social/Admin），系统运维负荷预算（OLU）面临超支挑战（预计峰值达到 22 人·天/周）。同时，玩家在充值掉单、物品丢失、卡死申诉等场景下的处理时效直接影响游戏口碑。

为达成“**极简稳定运营与卓越服务响应**”目标，系统引入智能化 **双 Agent 架构**：
1. **SRE 运维 Agent**：7×24h 自动化巡检、告警聚类降噪、根因定位（RCA）、灰度升级值守与异常节点隔离。
2. **客服 Agent（CS Agent）**：自动化玩家意图理解、跨服务链路对账、白名单小额补偿自动发放与工单流转。

## 5. 架构设计方针（ARC-053）

### 5.1 ARC-053：双 Agent 体系与 L0 确定性动作闸门边界（重要决定）

SRE 运维 Agent 与客服 Agent 只能生成、解释和提交带证据的 `ActionIntent`；它们自身不得直接写入玩家资产、数值、结算、配置或基础设施控制面。所有写动作必须由 L0 对签名、时效、nonce、动作/载荷绑定、权限、配额与幂等性进行确定性校验，并以默认拒绝处置未通过项。该约束由 ADR-0053 记录，且不得因模型、工具或运行时升级而放宽。

任何高额、争议性、跨域或不满足受控契约的请求必须升级至具名人类审批；Agent 的建议、草稿和告警聚类均不构成授权。
