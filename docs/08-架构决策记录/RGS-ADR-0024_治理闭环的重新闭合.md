## 1. 背景（Context）

RGS-REV-001横断审查检出18项问题，其中F-001指出：领域文档大量新增`FR-<域>-nnn`形式的ID，而附件C的可追溯性矩阵按子系统/NFR区分聚合，两套编号体系事实上分叉——领域ID无法机械聚合进既有矩阵，可追溯性名存实亡。

同时F-004指出ADR适用范围只覆盖RGS-REQ-001第10章，不含领域文档新增的ARC-018以后各项，构成规则空隙。

## 2. 决定（Decision）

建立**两级ID体系**：领域文档继续使用带域名段的域内ID（`FR-<域>-nnn`）以保持可读性，同时在附件C§7建立**ID归属登记表**声明每个域的归属子系统与NFR区分，使既有矩阵可继续机械聚合；`TBD`/`RSK`/`ISS`/`ADR`则统一分配全局主编号并在附件D登记。

配套：三层位阶（需求＞基本设计＞详细设计）、两层验收（既有AC＋域内`AC-<域>-nnn`经AC-019聚合进上线门禁）、ADR适用范围扩展至全部ARC。全部由CI机械校验。

## 3. 曾考虑并否决的方案（Alternatives Considered）

### 3.1 统一为全局单级ID（把全部领域FR重编号为全局序号）

概念最干净，无需归属登记表。否决理由：需要重编号既有数百条领域FR并同步修正全部交叉引用，一次性代价极高且极易出错；更根本的是，全局序号丧失了看编号即知所属域的可读性，而这一可读性在26个域的规模下价值很大。

### 3.2 放弃机械聚合，改为人工维护可追溯性矩阵

无需改动任何编号。否决理由：人工维护的矩阵在26域规模下必然漂移——本项目已多次实证这一点（README版本号漂移、附件C§8合计数算错、`NFR-SEC-008`被三份文档引用却从未定义）。可机械校验是此处不可让步的要求。

## 4. 结果与代价（Consequences）

**获得**：CI可机械校验ID登记完整性，四类历史缺陷（ID分叉、ADR规则空隙、验收标准游离、TBD未登记）被结构性堵住。

**付出**：新增域必须先在附件C§7注册方可使用ID，有流程成本；主编号须按序分配，不能随意取号。

**本决策未能解决的**：机械校验只能覆盖「编号是否登记」，覆盖不了「内容是否正确」。2026-08-17的审核即在全部检查通过的前提下仍查出7处实质引用错误（幽灵列名、章节号越界），事后补充了`check-cross-references.py`作为第5项检查——但这同样只是把可机械判定的边界向外推了一格，不是消除了该类风险。
