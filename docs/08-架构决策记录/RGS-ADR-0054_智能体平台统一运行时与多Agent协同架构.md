## 1. 决策背景

随着系统对智能化自治运维（SRE）、玩家服务（CS）、风控（GM）、数值模拟与生成式 NPC 的需求全面爆发，若将各类 Agent 零散嵌入各个业务服务，会导致：
1. **技术栈与依赖碎片化**（不同团队重复引入不同的 LLM 框架与向量库）。
2. **安全风险失控**（LLM 生成的未校验代码/指令直接侵入生产 DB）。
3. **运维与 Token 成本黑洞**。

---

## 2. 候选决策要点（待审批）

1. **候选：建立统一独立的 `13-智能体与Agent工程` 顶级架构域**，规范平台底座（033）、运营服务矩阵（034）与游戏仿真矩阵（035）。
2. **候选：统一 Agent 运行时与模型网关**。具体平台部署形态、LangGraph 版本和模型集成待 `TBD-NEURO-001`／CR 批准；Python 与 Rust 服务间仅可经 gRPC/Protobuf 受控边界交互，不采用 Rust FFI 作为跨服务运行时边界。
3. **候选安全基线：L0~L4 动作闸门（Action Gate）**。若获审批，所有写操作必须结构化为 `ActionIntent` 并经 Rust 核心强校验执行。
