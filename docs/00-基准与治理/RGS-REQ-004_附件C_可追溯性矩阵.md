## 1. 本附件的目的

本附件管理从业务需求到功能需求・架构・试验・验收标准的对应关系，保证以下事项：

| 编号 | 保证事项 |
|---|---|
| TR-001 | 全部业务需求已展开为1件以上的功能需求（**防止需求遗漏**） |
| TR-002 | 全部优先级「◎」的需求已挂接1件以上的试验（**防止验证遗漏**，AC-018） |
| TR-003 | 不存在无对应业务需求的功能需求（**防止过度实现**） |
| TR-004 | 全部架构设计方针都挂接了所要解决的课题（**排除无依据的方案**） |

**运维规则**：需求的追加・变更时，须同时更新本附件。本附件未同步更新的需求变更不得批准。
