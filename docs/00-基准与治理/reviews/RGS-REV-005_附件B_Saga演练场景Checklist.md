## §B.2 场景 1：正常 Saga 路径（玩家购买道具）

> 业务路径：player → economy（扣款）→ match（发放道具）→ social（通知）→ player（更新余额）

- [ ] **B2.1 Saga 启动**：玩家发起购买请求
- [ ] **B2.2 步骤 1**：player 域验证身份 + 余额
- [ ] **B2.3 步骤 2**：economy 域扣款（单 DB 事务 + Outbox）
- [ ] **B2.4 步骤 3**：match 域发放道具
- [ ] **B2.5 步骤 4**：social 域发通知
- [ ] **B2.6 步骤 5**：player 域更新余额
- [ ] **B2.7 Saga 完成**：所有步骤成功，inbox/outbox 清空
- [ ] **B2.8 断言**：
  - 玩家最终余额正确
  - 道具出现在 player 库存
  - 通知已发送
  - inbox/outbox 表无残留
  - 监控指标：所有步骤延迟 < 100ms

## §B.3 场景 2：补偿路径（中途失败）

> 业务路径：玩家购买道具，第 3 步（match 发放）失败

- [ ] **B3.1 Saga 启动**：玩家发起购买请求
- [ ] **B3.2 步骤 1-2 成功**：player 验证 + economy 扣款
- [ ] **B3.3 步骤 3 失败**：match 域发放道具失败（DB 写入错误）
- [ ] **B3.4 Saga 检测失败**：调解者通过 inbox 状态检测到 step 3 失败

- [ ] **B3.8 断言**：
  - 玩家最终余额 = 原始余额
  - 玩家库存无新道具
  - 失败日志完整（含 trace_id）
  - 监控指标：补偿完成时间 < 1s

## §B.4 场景 3：超时路径（节点失联）

> 业务路径：步骤 3 节点失联 30s+（per handoff §4.3 R2 K8s 健康检查超时）

- [ ] **B4.1 Saga 启动**：玩家发起购买请求
- [ ] **B4.2 步骤 1-2 成功**
- [ ] **B4.3 步骤 3 节点失联**：match 域 Pod 不可达 30s
- [ ] **B4.4 K8s 健康检查触发**：节点被标 NotReady
