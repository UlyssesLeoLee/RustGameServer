## §1 校准目标

5 域 Lead（player / economy / match / social / admin，per DEC-005 独立配置）各跑 **1-2 周真实工作样本**（PH-0 期间），按 **人·天 + token 双轨** 记录实际工作量。校准目标：

1. **验证 RGS-TS-001 v0.6 §6.2.1.2 人·天估算**（5 域 Lead × 14-18 周 ~266-540 / 周均 ~19-30）是否与实测一致
2. **验证 RGS-TS-001 v0.6 §6.2.2.3 token 估算**（5 域 Lead × 14-18 周 ~196M-468M / 周均 ~12M-26M）是否与实测一致
3. **校准换算公式 §6.2.2.1**（1 人·天 ≈ 100K-300K tokens）实测上下界
4. **校准单次 AI 协作会话 token 分布**（输入 / 输出 / 决策轮次）

校准结果决定：
- **接受**（偏差 < 30%）：§6.2 区间保留，PH-1 启动
- **升级 v0.7**（偏差 30-50%）：§6.2 区间修订，重新升版
- **NO-GO 升级**（偏差 > 50%）：53 启动条件不满足，§3.3 G-CODE 保持 Open

---

## §2 采集规范

### §2.1 人·天记录（v0.4 算法基线）

**记录单位**：1 人·天 = 1 名 Lead 1 个工作日（8 小时）的有效工时（含会议 / 决策等待 / 上下文切换）

| 字段 | 采集方式 | 备注 |
|---|---|---|
| 日期 | YYYY-MM-DD | 工作日（不含周末 / 节假日）|
| 任务类型 | PH-0.1 文档评审 / PH-0.2 DTL 字段级 / PH-0.3 SPEC 起草 / PH-0.4 会议 / ... | 标准化任务类型 |
| 有效工时 | 0.1-1.0 人·天 | 半天精度 0.5；超过 1.0 标 +OT |
| 备注 | 文字 | 关键事件 / 异常 |

**数据源**：
- 每日 self-report（每日 17:00 前提交）
- 会议日历（Calendar export）
- 工单 / IM 时间（必要时）

### §2.2 token 记录（v0.5 算法基线）

**记录单位**：1 token = 1 个 AI 协作 API 调用 token（输入 + 输出合并）

| 字段 | 采集方式 | 备注 |
|---|---|---|
| 日期 | YYYY-MM-DD | 同上 |
| 会话 ID | 唯一会话标识 | AI 协作平台会话 ID |
| 任务类型 | 同 §2.1 任务类型 | 与人·天任务对应 |
| 输入 tokens | 数字 | 用户 prompt + 上下文 |
| 输出 tokens | 数字 | AI 生成 + 工具调用 |
| 决策轮次 | 数字 | 单次会话内多轮对话次数 |
| 上下文窗口使用率 | 0.0-1.0 | 接近 1.0 需重启会话 |
| 备注 | 文字 | 关键事件 / 异常 |

**数据源**：
- AI 协作平台 API 统计（每日导出 CSV）
- 会话日志（用于回溯决策质量）
- Token 计费面板（如有）

### §2.3 双轨关联

每条人·天记录对应 0-N 条 token 记录（同一任务可能多次 AI 协作会话）；关联字段：日期 + 任务类型 + Lead 域。

## §4 校准公式与偏差处理

### §4.1 偏差计算

```
偏差 = |实测值 - 估算值| / 估算值 × 100%
```

### §4.2 偏差分级处理

| 偏差区间 | 处理 | RGS-TS-001 升版 |
|---|---|---|
| < 30% | 接受，§6.2 区间保留 | 不升版 |
| 30-50% | 修订 §6.2 区间，**升 v0.7** | 必须升 v0.7 |
| > 50% | **NO-GO 升级**：53 启动条件不满足 | v0.7 + 修订 handoff §4 Gate |
