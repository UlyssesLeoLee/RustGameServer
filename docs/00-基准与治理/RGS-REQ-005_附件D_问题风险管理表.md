## 3. 决定事项一览（ADR化对象）

本文档体系内**全部**架构设计方针（ARC-nnn），须作为以下ADR分别记录。**PH-1完成时点须存在ADR-0001〜0008。**

> **适用范围的扩展（ARC-025 GOV-ADR-001）**：本节原表述为"需求定义书第10章的架构设计方针"，该范围不含领域文档新增的ARC-018〜026，构成规则空隙（RGS-REV-001 F-004）。现扩展为"本文档体系内全部架构设计方针，不限于RGS-REQ-001第10章"。

> **ADR制定范围的收敛（2026-08-17，负责人指示）**：本表原将全部44项ARC一律登记为待制定ADR，长期停留在44/44「未制定」状态——登记行齐备而决策记录为零，`check-docs-consistency.sh`第2项却因只校验登记行存在性而持续报告"通过"，构成虚假保证（该检查已同步修正为输出制定进度）。
>
> 负责人判定：**事后为「本无取舍的决定」补写ADR，只会产出一批形式齐备、实则是对既成结论追认的文档，不如如实标注**。现按以下基准重新分类：
>
> - **确有取舍 → 制定ADR**（14项）：判定基准为三条同时成立——①当时确有具体、可辩护的替代方案；②选择该替代方案会实质改变架构；③否决理由不是"需求就是这么要求的"。
> - **决策显然 → 不单独立ADR**（30项）：或为既有标准解法的直接运用、或由更上层决策/需求直接推出、或属工程纪律成文。**状态列逐条注明归入该类的具体理由**，而非笼统略过。
>
> 「决策显然」**不等于不重要**——ARC-005会话世代、ARC-009 Outbox均属系统核心机制，只是其设计依据已完整记载于对应的BAS/DTL文档，独立ADR无法增加信息。若后续对某项产生实质争议，应届时补立ADR并在此更新状态。

> **编号管理（2026-08-20，2026-08-25更新）**：ARC的正式声明来源为 `RGS-REQ-*` 中含ARC编号的标题；普通正文、链接文字和测试输入仅为引用，不能创建新方针。`ARC-046`、`ARC-048〜050` 与 `ARC-052` 为明确保留的未分配编号，后续若启用必须先在本表登记对应ADR行；它们不应被连续编号检查误报为缺失。`ARC-047`已于2026-08-25由RGS-REQ-038正式声明启用（QUIC Datagram路径FEC编解码层），对应ADR-0047已在本表登记。`ARC-055` 与 `ARC-056` 是提案，已登记但在具名人类审批前不得作为生产基线。
