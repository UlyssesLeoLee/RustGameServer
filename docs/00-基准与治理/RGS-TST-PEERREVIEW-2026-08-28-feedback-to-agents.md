## F1. UT-09 pub 函数/结构体计数错误 + 与 TBD-09-02 自相矛盾

- **现象**：`RGS-TST-UT-09_工具集_单元测试设计书.md` 头表（第 18 行）写"`crates/rgs-certgen/src/main.rs`（4495 字节, **4 个 pub fn / 1 个 pub struct**）"；§1.2（第 68 行）"包含"列写"rgs-certgen crate **全部 pub fn** + Cli 结构体 + **4 个内部函数**（generate_ca / generate_server_cert / main 流程）"。

- **实证**：实读 `crates/rgs-certgen/src/main.rs`：
  - `struct Cli`（第 28 行）——无 `pub`。
  - `fn main()`（第 49 行）——无 `pub`（也不可能有，`main` 不允许 `pub`）。
  - `fn generate_ca(...)`（第 74 行）——无 `pub`。
  - `fn generate_server_cert(...)`（第 99 行）——无 `pub`。
  - 全文件共 **3 个函数、1 个结构体，0 个带 `pub` 关键字**。
  - §1.2 自己列出的函数名也只有 3 个（generate_ca / generate_server_cert / main），却称"4 个内部函数"，数字与其自己列举的清单本身不一致。
  - 同文档 §7 TBD-09-02（第 226 行）："rgs-certgen 是 bin 不是 lib，**只能通过 assert_cmd 黑盒测**"——已经承认没有可测的 pub 面，与 §1.2 声称"包含全部 pub fn"（一个空集合）矛盾：按字面执行，UT-09 的"包含"范围是空的，但整份文档又设计了 A~D 四个模块、19 条白盒 UT 用例。

- **性质判断**：不是单纯的字数误差，是头表统计错误（3 记成 4，0 pub 记成 4 pub）+ §1.2 自己列的清单和数字对不上 + 与文档自身 TBD 条目的事实性矛盾三处叠加。按"缺标比错标安全"的既定原则，这属于**错标**（断言了源码不存在的属性），且影响读者对该 crate 可测试面的判断。

- **要求**：
  1. 头表改为"3 个函数（均非 pub）/ 1 个结构体（非 pub）"或直接删除该计数，避免与 TBD-09-02 冲突。
  2. §1.2"包含"列改为准确描述实际测试路径（黑盒 `assert_cmd` + 文件系统断言），不要用"全部 pub fn"这类在此 crate 下为空集的表述。
  3. §1.2"4 个内部函数"改为与其自己列出的 3 个函数名一致。

## F4. peer-review §2.3 发现 #5 求和错误，且与同一报告紧邻表格矛盾

- **现象**：`peer-review-2026-08-28.md` 第 101 行："**发现 #5**：测试设计书的 23+20+25+19+15+10 = 112 ID 中，**已实现 22/GM08 + 10/工具集(0) + 0/ST08 TBD = 30 实现 + 82 TBD**"。

  - 数字来源问题：紧邻的上一段 §2.3 表格（第 77~97 行）逐行标注 ✅/⚠️ TBD，把标 ✅ 的行数相加：UT-08 = A(6)+B(3)+C001(1)+D(7)+E(4) = 21；IT-08 = A(3)+B(5)+C(4) = 12；ST-08 = A(6)+B(3) = 9；工具集 09（UT/IT/ST 全标 ⚠️ TBD）= 0。合计 **ID 级**已实现 = 21+12+9+0 = 42，不是 22。"发现 #5"里的"22/GM08"看起来是把 UT-08 的 ID 总数（22，参见 F3 相邻发现 #1 已核实为 22）误当成"已实现数"代入，而非该报告自己表格算出的 21+12+9=42。
