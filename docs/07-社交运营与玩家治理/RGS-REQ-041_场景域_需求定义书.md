# 1. 背景与范围

## 1.1 背景

`crates/scene-service/` 是 RGS 7 域扩展（per 路线图 §3 W5 + 9/4 MD §2）下独立拆分的场景微服务。其设计**承接**既有 RT（runtime）场景的扩展能力——大量具体游戏场景的精细化逻辑（NPC / 触发器 / 副本内部 / 世界地图 / 战场地图等）。

本域覆盖 1 个 gRPC service（SceneService）、148 个 RPC（含 148 个细分场景操作）。其中 30 RPC 为真实业务逻辑（场景加载 / 玩家进入 / 玩家离开 / 实体管理 / 触发器），118 RPC 为 Unimplemented stub（Phase 3 业务实装）。

| Service | proto | RPC 数 | 业务实装策略 |
|---|---|---|---|
| SceneService | proto_scene | 148 | 真实逻辑：场景生命周期 + 实体管理 + 触发器 |

## 1.2 范围边界

**In-Scope**：
- 场景加载 / 卸载 / 持久化
- 玩家进入 / 离开场景（与既有 RT 场景间转移衔接）
- 实体管理（NPC / 怪物 / 道具 / 装饰）
- 触发器系统（区域触发 / 事件触发 / 任务触发）
- 场景内同步（复用 ARC-002 既有 AOI）

**Out-of-Scope**：
- 战斗内部逻辑（属 battle-service 范畴）
- 场景间转移的低层机制（属 RT 既有职责，FR-RT-008）
- 客户端地图渲染 / LOD（属客户端范畴）
- 大厅本身（属 RGS-REQ-016 大厅社交通信范畴）
- 副本内部（属 battle-service InstanceService 子范畴）

## 1.3 与既有基础设施的关系（避免重复建设）

| 既有机制 | 本域使用方式 |
|---|---|
| ARC-001 Actor 粒度 = 场景单位 | 一个 SceneService 实例 = 一个 SceneActor，复用 ARC-001 状态机 |
| ARC-002 状态同步 + 客户端预测 | 场景内同步走既有 AOI 差分快照；本域不另建同步算法 |
| ARC-008 5 独立 DB → 7 域扩展 | 本域落位独立 `scene_db`（不与 player / social / economy 混库） |
| RGS-BAS-013 §2.2 大厅作为特殊场景 | 战斗场景从大厅转入走既有 FR-RT-008 机制 |
| RGS-BAS-026 匹配系统 | 玩家进入 PVP 场景**必须**经 MT 既有匹配流程 |

# 3. 业务需求 (BR)

## BR-SCN-001 场景生命周期

RGS 应支持场景的完整生命周期：
- **加载**：从 SceneConfig 创建 SceneInstance
- **运行**：玩家进出、实体管理、触发器触发
- **持久化**：场景内关键状态写入 scene_db
- **卸载**：场景实例清理（无玩家 + 无 NPC 持久任务）

**验收**：场景从加载到卸载的全链路可稳定运行。

## BR-SCN-002 玩家进出场景

- 玩家可进入指定场景（按 SceneConfig 校验准入条件）
- 玩家可离开场景（主动 / 被动 / 断线）
- 玩家进出场景**必须**经既有 FR-RT-008 场景间转移机制（不绕过）

**验收**：玩家从大厅 → 场景 → 大厅的完整路径可稳定运行。

## BR-SCN-003 实体管理

- NPC / 怪物 / 道具 / 装饰四类实体的 CRUD
- 实体属性（hp / 位置 / 状态）的运行时维护
- 实体 AI（per Config 驱动）

**验收**：4 类实体均能 CRUD，属性变更触发 AOI 广播。

## BR-SCN-004 触发器系统

- 区域触发：玩家进入 AOI 区域时触发
- 事件触发：玩家执行动作时触发
- 任务触发：玩家任务进度满足时触发

**验收**：3 类触发器均能配置 + 触发 + 回调。

## BR-SCN-005 场景配置驱动

- 场景由 SceneConfig 数据驱动
- 新增场景**必须**仅通过 SceneConfig 上线（per ARC-049 数据驱动原则）
- **不**为每个新场景新建独立 service / crate

**验收**：新增场景无须代码改动。

# 4. 功能需求 (FR)

## 4.1 场景加载与卸载

| ID | 需求 |
|---|---|
| FR-SCN-001 | SceneService `LoadScene` **必须**根据 SceneConfig 创建 SceneInstance |
| FR-SCN-002 | 场景加载**必须**支持从 scene_db 读取持久化状态（如任务进度、NPC 死亡状态） |
| FR-SCN-003 | SceneService `UnloadScene` **必须**清理无玩家 + 无持久任务的场景实例 |
| FR-SCN-004 | 场景加载 / 卸载**应当**走 ARC-002 AOI 差分快照机制，不另建同步层 |

## 4.2 玩家进出场景

| ID | 需求 |
|---|---|
| FR-SCN-010 | `EnterScene` **必须**校验准入条件（等级 / 任务前置 / SceneConfig.gate） |
| FR-SCN-011 | `LeaveScene` **必须**支持主动（玩家请求）/ 被动（场景销毁）/ 断线（per NFR-SCN-003）三类触发 |
| FR-SCN-012 | 玩家进出场景**必须**经既有 FR-RT-008 场景间转移机制，**不**绕过 |
| FR-SCN-013 | 玩家离开场景**必须**持久化玩家在场景内的关键状态（如任务进度、buff） |

## 4.3 实体管理

| ID | 需求 |
|---|---|
| FR-SCN-020 | 4 类实体（NPC / 怪物 / 道具 / 装饰）**必须**全部 CRUD 化 |
| FR-SCN-021 | 实体属性变更**必须**触发 AOI 广播（per ARC-002 既有） |
| FR-SCN-022 | 实体 AI **应当**由 Config 驱动（per ARC-049 反例原则） |
| FR-SCN-023 | 怪物死亡 / 道具拾取**必须**触发场景状态变更并落位 scene_db |

## 4.4 触发器系统

| ID | 需求 |
|---|---|
| FR-SCN-030 | 区域触发**必须**支持矩形 / 圆形 / 多边形 3 种形状 |
| FR-SCN-031 | 事件触发**必须**支持动作 ID + 参数匹配 |
| FR-SCN-032 | 任务触发**必须**经既有 GSM 任务系统（per RGS-BAS-014 §3），**不**在 scene 内另建任务 |
| FR-SCN-033 | 触发器回调**应当**支持进入 / 离开 / 停留 3 种时序 |

# 5. 非功能需求 (NFR)

| ID | 类别 | 内容 | 目标值 / 判定基准 |
|---|---|---|---|
| NFR-SCN-001 | 性能 | 场景加载 P99 延迟 | < 500ms（per NFR-OP-005 既有，场景加载属冷启动开销） |
| NFR-SCN-002 | 一致性 | 场景状态持久化**必须**与玩家操作具备同一事务边界 | per RGS-DTL-001 §3.2 OCC + 幂等 |
| NFR-SCN-003 | 可恢复 | 玩家断线后**必须**能在 N 分钟内重连并恢复场景状态 | 配置可调（N 由策划确认） |
| NFR-SCN-004 | 容量 | 单场景**应当**支持最多 N 个玩家同时在场（N 由 SceneConfig.max_players 决定） | per RGS-REQ-025 ARC-040 容量分级 |
| NFR-SCN-005 | 安全 | 触发器回调**必须**服务器权威执行（per NFR-SE-001），客户端**不得**直接触发 |

# 6. 架构设计方针 ARC-049

本节为 RGS-REQ-001 第 10 章架构方针体系的延续，编号紧接 ARC-048。

## 6.1 ARC-049：场景域数据驱动 + AOI 复用原则

| 项目 | 内容 |
|---|---|
| **决定** | 场景由 SceneConfig 数据驱动，新增场景无须代码改动；场景内同步**严格**复用 ARC-002 既有 AOI 机制，本域不另建同步算法；不绕过既有 RT 场景间转移（FR-RT-008） |
| **理由** | [游戏A]类游戏的场景数量通常达到 100+（世界地图 / 副本 / 战场 / 活动场景等），若每个场景单独建模，会导致 SceneService 在 1 年内产生大量冗余代码。本原则与 ARC-046 战斗域反例原则同源 |
| **数据驱动配置的承载机制** | ① SceneConfig 通过 RGS-REQ-009 插件体系下的"特性开关 + 配置数据"承载（per ARC-021）；②**不**使用沙箱脚本；③**不**新建独立 service / crate |
| **新增场景的标准流程** | ①策划 / 关卡设计提交 SceneConfig 数据 ②经 ARC-021 既有插件注册通道上线 ③无须代码改动，无须重启服务 |
| **否决方案** | "为每个新场景新建独立 service / crate"——直接违反 ARC-018（功能挂载评审）+ [游戏A]反例原则，已否决 |
| **适用范围** | 本域所有场景（世界地图 / 副本 / 战场 / 活动场景 / 城市等） |

# 7. 验收标准

| ID | 验收标准 |
