# 1. 背景与范围

## 1.1 背景

`crates/pvp-full-service/` 是 RGS 7 域扩展（per 路线图 §3 W5 + 9/4 MD §2）下独立拆分的竞技扩展微服务。其设计**承接** battle-service PvPService 的核心 PVP 战斗逻辑，但承担**竞技专用**的扩展功能：PVP 段位 / 赛季 / 排行榜 / 匹配池边界 / 战绩回放 / 观战等。

本域覆盖 1 个 gRPC service（PvpFullService）、30 个 RPC（含 1 HealthCheck）。其中 20 RPC 为真实业务逻辑（竞技赛季 / 段位 / 战绩 / 排行榜 / 匹配池），10 RPC 为 Unimplemented stub（Phase 3 业务实装）。

## 1.2 范围边界

**In-Scope**：
- PVP 赛季生命周期（创建 / 运行 / 结算 / 归档）
- 段位系统（青铜〜[顶级段位] + [次顶级段位] + [顶级段位]）
- 战绩记录（历史 PVP 对局记录）
- 排行榜（PVP 段位榜 + 胜率榜 + 积分榜）
- 匹配池边界（per RGS-REQ-029 既有）
- 观战（实时观战 + 录像回放）

**Out-of-Scope**：
- PVP 核心战斗状态机（属 battle-service PvPService 范畴）
- 客户端 PVP 预测算法（属 ARC-002 既有同步层）
- GM 工具对竞技域的处置（属 RGS-REQ-007 GM 工具既有）
- 经济系统（战斗结算后的奖励）（属 battle-service + EC 既有）

## 1.3 与既有基础设施的关系（避免重复建设）

| 既有机制 | 本域使用方式 |
|---|---|
| ARC-011 Saga 单调解者 | 竞技结算**必须**经 EC 既有路径（per RGS-REQ-013 FR-GOV-001） |
| ARC-021 插件热插拔 | 赛季规则作为特性开关 + 配置数据承载 |
| RGS-BAS-026 匹配系统 | 竞技匹配池边界**必须**经 MT 既有 |
| RGS-BAS-014 排行榜任务成就 | 段位 / 积分走既有 GSM 派生视图 |
| battle-service PvPService | 战斗状态机复用，本域不重建 |
| replay-extra-service | 录像回放走既有，本域不重建 |

# 3. 业务需求 (BR)

## BR-PVP-001 赛季生命周期

RGS 应支持 PVP 赛季的完整生命周期：
- **创建**：从 SeasonConfig 创建赛季
- **运行**：玩家段位升降、积分变化、排行榜更新
- **结算**：赛季结束时的段位继承、奖励发放
- **归档**：赛季数据归档（per RGS-BAS-014 赛季重置既有）

**验收**：赛季从创建到归档的全链路可稳定运行。

## BR-PVP-002 段位系统

- 8 段位（青铜 / 白银 / 黄金 / 铂金 / 钻石 / 大师 / [次顶级段位] / [顶级段位]）
- 段位升降规则（per RankConfig）
- 段位保护（连败保护 per RGS-BAS-026 §4 既有）

**验收**：8 段位升降规则经端到端验证。

## BR-PVP-003 战绩记录

- 每场 PVP 对局的完整记录（双方 ID / 结果 / 段位变化 / 积分变化）
- 玩家可查询自己 30 天内战绩
- 玩家可查询他人公开战绩（仅战绩存在 + 段位，不含装备）

**验收**：战绩可分页 / 过滤 / 实时刷新。

## BR-PVP-004 排行榜

- 段位榜（按段位 + 积分排序）
- 胜率榜（按胜率排序，最少 N 场）
- 积分榜（按当前积分排序）

**验收**：3 类排行榜可分页 / 过滤 / 实时刷新。

## BR-PVP-005 观战

- 实时观战：玩家可观看正在进行中的 PVP 对局
- 录像回放：玩家可观看已结束 PVP 对局的录像（per replay-extra-service 既有）

**验收**：观战延迟 < 2 秒（实时）/ 录像正常加载（回放）。

# 6. 架构设计方针 ARC-050

本节为 RGS-REQ-001 第 10 章架构方针体系的延续，编号紧接 ARC-049。

## 6.1 ARC-050：竞技域扩展 + 复用 battle PvP 数据驱动原则

| 项目 | 内容 |
|---|---|
| **决定** | 竞技域仅承担"竞技专用扩展功能"（赛季 / 段位 / 战绩 / 观战），**不**重复实现战斗状态机；战斗状态机**严格**复用 battle-service PvPService（per ARC-046）；排行榜**严格**复用 GSM 既有派生视图 |
| **理由** | [游戏A]类游戏的 PVP 系统涉及"战斗 + 段位 + 赛季 + 排行榜 + 观战"五层，若各层独立建模，会导致 pvp-full 在 1 年内与 battle PvPService 产生大量重复代码 |
| **扩展功能的承载机制** | ①赛季规则 / 段位规则作为 ARC-021 既有插件通道承载；②战绩 / 排行榜作为派生视图，**不**在 pvp-full 内自建；③观战走 replay-extra-service 既有 |
| **新增赛季变体的标准流程** | ①策划 / 数值提交 SeasonConfig 数据 ②经 ARC-021 既有插件注册通道上线 ③无须代码改动 |
| **否决方案** | "在 pvp-full 内自建战斗状态机 / 自建排行榜"——直接违反 ARC-011（不绕过 EC）+ ARC-018（不绕过既有 GSM）+ [游戏A]反例原则，已否决 |
| **适用范围** | 本域所有竞技专用功能（赛季 / 段位 / 战绩 / 观战等） |
