## 1. 目的

RGS-REQ-028 §5 已规定"案件形成"与"惯犯识别"，但**风控规则多为硬编码阈值**（如"1 小时内移动 > 1000m 报警"），存在以下问题：

- 阈值调整需重新发布服务（违反 ARC-016 无停机热更）
- 不同游戏模式（PvP/PvE）需不同阈值，硬编码难表达
- 风控运营人员需写代码才能调阈值，违反"工程化"原则
- A/B 测试反作弊规则不灵活

本补强引入**风控规则 DSL**（Domain Specific Language），以 Rhai 作为候选脚本引擎；RGS-ADR-0020 当前状态为“已制定・待评审”，因此 ADR 获批前仅可在隔离测试环境验证，**不得**作为生产热更新依据。

## 2. 业务需求

| ID | 需求 | 优先级 |
|---|---|---|
| BR-ANT-101 | 风控规则可热更新（不重启服务） | 高 |
| BR-ANT-102 | 规则变更可灰度（按 channel 路由） | 中 |
| BR-ANT-103 | 规则执行可观测（命中次数、误判率） | 高 |
| BR-ANT-104 | 规则执行有超时上限 | 高 |
| BR-ANT-105 | 规则可回滚 | 高 |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-ANT-005 | DSL 语法：基于 Rhai 脚本，定义 `rule(ctx) -> Score/Decision` 函数 |
| FR-ANT-006 | 内置函数：`ctx.player`, `ctx.action`, `ctx.history`, `ctx.score` 等受限 API |
| FR-ANT-007 | 规则仓库：每个 rule 一个 .rhai 文件，按 `(channel, version)` 管理 |
| FR-ANT-008 | 热更新：在控制面、签名和网络健康时，仓库变更 → 推送至规则引擎 → 5s 内全节点生效；分区时按 DTL-025 v0.3 §6.5 fail-closed |
| FR-ANT-009 | 超时控制：单规则执行 100ms 超时，超时按 0 分处理（fail-safe） |
| FR-ANT-010 | 灰度：channel 标签（`canary` / `stable`），可逐步放量 |
| FR-ANT-011 | 回滚：经签名 manifest 回退至上一版本；在控制面和网络健康时 5s 内全节点回滚，未确认节点不得计为成功 |
| FR-ANT-012 | 沙箱：Rhai 受限 API（禁止文件系统、网络），仅可访问 ctx |

## 4. 非功能需求

| ID | 目标值 |
|---|---|
| NFR-ANT-101 | 单规则执行 p99 < 50ms |
| NFR-ANT-102 | 控制面、签名和网络健康时规则仓库推送至全节点 ≤ 5s；分区期以 fail-closed 为正确行为 |
| NFR-ANT-103 | 规则变更不停服（NFR-AV-007） |
| NFR-ANT-104 | 规则误判申诉率 ≤ 5% |
| NFR-ANT-105 | 沙箱逃逸检测：0 例 |

## 5. 架构决定

| 编号 | 决定 |
|---|---|
| ARC-043-1 | DSL 引擎候选：**Rhai 1.x**（RGS-ADR-0020 已制定・待评审；获批前生产开关保持 `false`） |
| ARC-043-2 | 规则仓库：Git 仓库 + GitOps 推送，落地至 S3/MinIO |
| ARC-043-3 | 规则推送：NATS 订阅（已用）或 PostgreSQL LISTEN/NOTIFY |
| ARC-043-4 | 沙箱：白名单 API（ctx.\* + math + string + array + 时间），禁止 fs/net/syscall |
| ARC-043-5 | 灰度按 channel（与 CDN 共用灰度机制，RGS-REQ-030-ADD1 §3 FR-CDN-033） |
| ARC-043-6 | 规则版本：单调递增 `version` 字段，节点本地缓存最近 3 版本 |

## 6. 验收标准

| ID | 描述 |
|---|---|
| AC-ANT-101 | 控制面、签名和网络健康时规则推送 5s 内全节点生效 |
| AC-ANT-102 | 单规则 p99 < 50ms |
| AC-ANT-103 | 控制面、签名和网络健康时规则回滚 5s 内全节点回退；未确认节点不计通过 |
| AC-ANT-104 | 沙箱逃逸 0 例（红队测试覆盖） |
| AC-ANT-105 | 误判率 ≤ 5% |
