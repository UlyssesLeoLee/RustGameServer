## 1. 目的

RGS-REQ-030 的 FR-CDN-006 给出“默认自托管开源”方向，但该方向**不构成任何组件的已批准选型**，且未细化：
- 自托管场景下的边缘缓存策略
- 资源回源失败时的降级路径
- 灰度发布与回滚的 CDN 行为
- 跨区域分发的一致性

本补强给出“边缘缓存 + 经批准分发后端”的可验证契约；自托管与商业实现均须先通过同一审批门禁。

## 2. 业务需求

| ID | 需求 | 优先级 |
|---|---|---|
| BR-CDN-101 | 边缘命中延迟 < 50ms（用户就近） | 高 |
| BR-CDN-102 | 回源失败时不阻塞玩家启动 | 高 |
| BR-CDN-103 | 灰度推送可快速回滚 | 高 |
| BR-CDN-104 | 资源签名校验 100% | 高 |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-CDN-030 | 边缘节点缓存：经批准的 HTTP 边缘代理/缓存后端缓存 manifest 与 patch，TTL 5min |
| FR-CDN-031 | 缓存键：`{channel}/{version}/{region}/{file}`，含 region（地理）+ channel（灰度桶） |
| FR-CDN-032 | 回源回退：边缘 miss → 经批准的 `DistributionBackend` 源站 → 后端失败则回退上一稳定版本 |
| FR-CDN-033 | 灰度发布：channel 字段携带灰度桶（`canary` / `stable` / `legacy`），边缘按 channel 路由 |
| FR-CDN-034 | 快速下线：推送新 channel 0% 流量配置 → 30s 内全部流量切回 stable |
| FR-CDN-035 | 强制更新：客户端版本低于 `min_supported_version` 时，边缘返回 302 → 引导页 |

## 4. 非功能需求

| ID | 目标值 |
|---|---|
| NFR-CDN-101 | 边缘命中率 ≥ 80%（manifest）、≥ 95%（patch 包） |
| NFR-CDN-102 | 回源成功率 ≥ 99.9% |
| NFR-CDN-103 | 灰度切流时长 ≤ 30s |
| NFR-CDN-104 | 强制更新判定 < 100ms |
| NFR-CDN-105 | 生产激活的后端及其直接/传递组件必须具备可核验的 BOM、许可证/商业条款审查记录与适用 ADR；未批准候选不得启用。 |

## 5. 架构决定

| 编号 | 决定 |
|---|---|
| ARC-045-1 | 生产部署路径只允许使用**经批准的** `DistributionBackend`；若选择自托管，MinIO、Nginx、Varnish 均仅是候选，须先完成 BOM、许可证审查与 ADR，不能视为默认批准。 |
| ARC-045-2 | 商业 CDN 作为可插拔 `DistributionBackend`；启用前同样须完成 BOM/合同与许可证审查、架构与安全评审，并取得 ADR。 |
| ARC-045-3 | 灰度发布用 channel 标签，**不** 用 IP 段（避免灰度泄漏） |
| ARC-045-4 | 强制更新用客户端版本号判定，**不** 用日期（避免时钟漂移） |
| ARC-045-5 | 资源签名使用 Ed25519（OSI 许可，NIST 标准） |

## 6. 验收标准

| ID | 描述 |
|---|---|
| AC-CDN-101 | 边缘命中延迟 p99 < 50ms |
| AC-CDN-102 | 模拟边缘 miss → 回源 → 1s 内返回 |
| AC-CDN-103 | 灰度 100% 切回 stable ≤ 30s |
| AC-CDN-104 | 强制更新判定 100ms 内 |
| AC-CDN-105 | 100% 资源签名校验通过 |
| AC-CDN-106 | 每个生产激活后端均可追溯至 BOM、许可证/商业条款审查与 ADR；部署门禁拒绝缺失或未批准的配置。 |
