# 5D 集成校验 (Cross-D Integration Check)

> 单层通过了不代表整体对。这一层专查 D1→D2→D3→D4→D5 的**接口一致性**。

---

## 1. 价值主张 ↔ 信息架构

- [ ] D2 顶层导航主题句 = D1 价值主张的同义改写
- [ ] D2 不出现 D1 反指标禁止的项 (如: 监控 NSM 反对"页面停留时长",则 D2 不应把"停留时长"做成指标)

## 2. 信息架构 ↔ 交互流程

- [ ] D3 每条旅程引用 D2 给出的入口 (≥ 3)
- [ ] D3 状态机对象的字段与 D2 实体字段一致
- [ ] D3 表单必填 ≤ 7 项与 D2 内容模型必填 ≤ 7 项对应

## 3. 交互流程 ↔ 视觉语言

- [ ] D3 状态机每个状态都有 D4 chip 样式映射
- [ ] D3 旅程规格中的字段分组,与 D4 form layout 一致
- [ ] D3 错误路径对应 D4 错误样式 token

## 4. 视觉语言 ↔ 工程交付

- [ ] D4 token JSON 是 D5 CSS 变量 / Tailwind theme 的唯一来源
- [ ] D4 栅格断点是 D5 媒体查询 / 容器查询的配置来源
- [ ] D4 z-index 表是 D5 全局样式表唯一来源
- [ ] D4 减弱动效是 D5 prefers-reduced-motion 配置来源

## 5. 工程交付 ↔ 战略

- [ ] D5 性能预算与 D1 NSM 的"质量阈值"对齐 (例:NSM 含"快速",预算就要 LCP ≤ 2.5)
- [ ] D5 ADR 中"撤销条件"被 D1 反指标列表引用
- [ ] D5 监控事件 schema 与 D3 旅程事件命名一致

---

## 集成失败的反模式

- ❌ D1 说"快速",D5 预算却写 LCP ≤ 5s → 战略与工程脱节
- ❌ D4 token 与 D5 CSS 变量各写一套 → 改色两边改
- ❌ D3 状态机 5 态,D4 视觉只画了 3 态 → 视觉与逻辑脱节
- ❌ D5 监控事件名与 D3 不一致 → 跨团队看不懂

---

## 一致性审计建议

每季度跑一次集成校验:
1. 从 D1 提取所有 NSM / 反指标 / Persona
2. 从 D5 提取所有监控事件 / 性能预算
3. 做名词+定义的双向 grep,缺失或不一致即报警
