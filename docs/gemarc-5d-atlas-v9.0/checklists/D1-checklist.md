# D1 出口校验清单 (Checklist)

> 自检用。跑这份清单前先把模板填到 D1-concept-brief.template.md。

## A. 价值主张

- [ ] 一句话能讲清 (≤ 25 字)
- [ ] 至少 1 个功能 / 社会 / 情感 任务都被覆盖
- [ ] 痛点严重度有数字
- [ ] Pain Relievers 明确对应 Pains
- [ ] Gain Creators 明确对应 Gains
- [ ] 替代弹性有答案

## B. Persona

- [ ] ≥ 3 个切片,**含 1 个非目标**
- [ ] 每个切片有设备 / 时段 / 任务 / 痛点 / 容忍度
- [ ] 没有"全人类"型空泛描述

## C. NSM + Anti-Metric

- [ ] 1 个 NSM 有名字 / 定义 / 计数口径 / 周期 / 基线 / 90d 目标
- [ ] ≥ 3 个反指标
- [ ] NSM 不是纯计数 (有复合性)
- [ ] 反指标有"破阈值"才报警逻辑

## D. 范围

- [ ] In-scope 每项 1 行 + 理由
- [ ] Out-of-scope 每项 1 行 + 理由
- [ ] Next-scope 留 hook 名

## E. 硬约束

- [ ] 每条都有证据链接 (git / 官方文档 / 合同)
- [ ] 不可动摇项 ☐ 已选
- [ ] 资源上限明确 (预算 / 人 / 时)

## F. 反向假设

- [ ] P0 假设 ≥ 1
- [ ] 每个假设有可执行证伪方式
- [ ] 验证成本与优先级排好

## G. 反对者签字 (出口判据 ☐)

- [ ] ≥ 1 真人或临时代签,带立场 (反对/弃权/附条件)

## H. 已知缺口 (出口判据 ☐)

- [ ] 列了未答 / 未访 / 未基线 项

---

## 通过标准
- 所有 A-G 全部 ☑
- H 的缺口有"补足方式"

## 不通过的反模式
- ❌ "战略很重要,我们大致对齐了" → 大致对齐 = 没对齐
- ❌ Persona = "年轻人 / 上班族 / 老人"  → 切片错位
- ❌ NSM 写成 "用户数" / "GMV"  → 没复合性
- ❌ Out-of-scope 写"一切能想到的"  → 真出问题时无锚
- ❌ 硬约束 = "我们想 / 领导说"  → 缺证据
