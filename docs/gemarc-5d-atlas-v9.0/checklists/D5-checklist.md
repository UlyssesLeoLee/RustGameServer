# D5 出口校验清单

## A. ADR

- [ ] 每技术选型都有 ADR
- [ ] 每 ADR ≥ 2 个备选方案
- [ ] 每 ADR 有撤销条件 (可观察)
- [ ] ADR 索引表完整

## B. 性能预算

- [ ] LCP / INP / CLS 阈值写入 CI
- [ ] 资源预算 (JS / CSS / 字体 / 图片) 写入 CI
- [ ] API P50 / P95 / P99 写入 CI
- [ ] 超阈值阻断合并

## C. 可观测性

- [ ] 日志结构化 (JSON) 含 trace_id
- [ ] 指标 RED + USE
- [ ] 链路 OpenTelemetry 或同等方案
- [ ] 用户旅程事件埋点齐 (per D3.7)
- [ ] 系统事件埋点齐 (boot / deploy / config_reload)

## D. 告警

- [ ] 4 级 (P0-P3) 阈值 + 响应
- [ ] 值班表有人认领
- [ ] 告警有 runbook 链接

## E. 可访问性工程化

- [ ] axe-core / pa11y-ci 接入 CI
- [ ] 阻断阈值 ≥ 95
- [ ] 真人 ≥ 5 用户验证 (含屏读 / 色盲 / 仅键盘)
- [ ] 减弱动效工程实装

## F. 测试金字塔

- [ ] 单元 / 集成 / E2E 比例 60/30/10
- [ ] bug 修复前先写复现测试
- [ ] 测试名描述"做什么"
- [ ] E2E 关键旅程 ≤ 7 条
- [ ] 每次 commit 测试配额

## G. 发布策略

- [ ] 选型 (滚动 / 蓝绿 / 灰度 / flag) 写明
- [ ] 回滚脚本化
- [ ] 季度回滚演练
- [ ] 数据库迁移双向 + ≥ 7 条铁律

## H. 安全

- [ ] 凭据永不入仓 (CI 扫描)
- [ ] 凭据永不打印 (CI 扫描)
- [ ] 锁版本 + 定期 audit
- [ ] SBOM 入库
- [ ] mTLS / 强加密业务级

## I. 域划分

- [ ] 域 = 业务 + 数据 + API
- [ ] 跨域走契约
- [ ] 域内独立升级
- [ ] API 兼容 + 弃用期

## J. 已知缺口

- [ ] 性能预算基线缺
- [ ] 值班未指定
- [ ] a11y 真人未做
- [ ] 回滚演练未跑
- [ ] SBOM 未生成

---

## 通过标准
A-I 全部 ☑,J 的缺口有补足计划。

## 反模式
- ❌ "先上线再优化" → 上线后无监控 = 黑盒
- ❌ 监控三支柱"接入了"但没人看 → 接了不等于用
- ❌ 测试金字塔倒置 (e2e 多单元少) → 跑不动就停
- ❌ 凭据在 README 写明"这是测试密码" → 入仓即破规
- ❌ 数据库删字段直接 drop → 不可逆
