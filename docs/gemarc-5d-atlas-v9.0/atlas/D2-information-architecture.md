# D2 — Information Architecture（信息架构层）

> **5D Atlas v9.0 · D2/5**
> **目的**: 把 D1 的价值主张拆成可被用户**找到、理解、信任**的内容结构。
> **失败模式**: 信息架构只画一级导航 —— 用户找不到东西,再好的 D3/D4 都白做。

---

## 0. 本层回答的核心问题

| # | 问题 | 不回答的后果 |
|---|---|---|
| Q1 | **内容由什么组成** (实体 / 字段 / 关系) | D4 不知画什么,D5 不知存什么 |
| Q2 | **如何分类** (分类法 / 上位/下位) | 用户找不到入口,搜索成本陡增 |
| Q3 | **如何组织** (层级 / 扁平 / 标签) | 失忆症用户每次都从首页重新走 |
| Q4 | **如何命名** (标签系统) | 同义词爆炸,搜索框半失能 |
| Q5 | **如何检索** (搜索 / 推荐 / 路径) | 大盘数据下用户卡死 |
| Q6 | **如何演化** (新增/合并/删除的规则) | 一年后 IA 变成"祖先之城" |

## 1. 内容模型 (Content Model)

```markdown
## 实体 / Entity
- 实体 1 (例如 "任务卡")
  - 必填字段: ___
  - 可选字段: ___
  - 状态机: ___
  - 关联实体: ___

## 关系 / Relationship
- 任务卡 → 用户 (N:M)
- 任务卡 → 项目 (N:1)
- ...

## 类型 / Type
- 字符串 / 富文本 / 枚举 / 数字 / 日期 / 引用
- 每种类型的显示规则: 截断长度 / 默认值 / 校验

## 来源 / Source
- 谁产生 (用户 / 系统 / 外部)
- 谁修改 (RACI)
- 谁删除 (软删/硬删?)
```

**判据**: 每个字段都必须能回答"为什么必须有它"。无答案字段就是范围蔓延。

## 2. 分类法 (Taxonomy)

### 2.1 单维 vs 多维

| 维度 | 例子 | 是否互斥 | 备注 |
|---|---|---|---|
| 主题 | 游戏 / 工具 / 资讯 | 否 (可多选) | 用户多维度感知 |
| 时效 | 今日 / 本周 / 永久 | 否 | 时间维度独立 |
| 对象 | 个人 / 团队 / 组织 | 否 | 权限维度 |
| 状态 | 草稿 / 发布 / 归档 | 是 | 同一对象只能有一态 |

**判据**: 互斥维度只能选一个;非互斥可多选,但**避免 > 3 维筛选**同时打开 —— 用户认知超载。

### 2.2 上位 / 下位关系

```markdown
- [主题] 游戏
  - 策略
  - 动作
  - 模拟
- [主题] 工具
  - 调试
  - 分析
```

**判据**: 每个分类节点必须有**示例与反例**;否则下游会用错。

## 3. 站点地图 (Sitemap)

### 3.1 三层结构

```
L0 主导航 (≤7 项)
  L1 子导航
    L2 详情页
```

**判据**: L0 永远 ≤ 7 项 (Miller 7±2);L1 ≤ 9 项;L2 不限。

### 3.2 多入口原则

```markdown
## 对象 A
- 入口 1: 首页 → 列表 → 详情 (主路径)
- 入口 2: 全局搜索 → 详情 (搜索路径)
- 入口 3: 相关推荐 → 详情 (伴随路径)
- 入口 4: 个人主页 → 我的 → 详情 (私域路径)
```

**判据**: 每个核心对象至少 **3 个独立入口**。否则用户离开主路径就迷路。

## 4. 标签系统 (Labeling)

### 4.1 命名冲突矩阵

| 场景 | A 用词 | B 用词 | 解决 |
|---|---|---|---|
| 同一概念 | "任务" | "工作" | 选其一为**规范词**, 另一作引号 fallback |
| 同一词多义 | "卡片"=任务卡 | "卡片"=积分卡 | 不允许;消歧或换词 |

### 4.2 同义词表 (Synonym Map)

```markdown
| 规范词 | 同义词 | 用途 |
|---|---|---|
| 任务 | 作业 / 工作 / 事项 | 用户可见可选其一;全文索引合流 |
| 项目 | 项目 / 看板 / 空间 | 仅首页 slogan 用"空间" |
```

## 5. 检索设计 (Findability)

### 5.1 三路径成本对比

| 路径 | 适用 | 设计要点 |
|---|---|---|
| 浏览 | 用户不知道要找什么 | IA 完备,L0-L2 视觉层清楚 |
| 搜索 | 用户知道关键词 | 同义词表 + 模糊匹配 + 拼写纠错 |
| 推荐 | 用户没动机找 | 算法黑盒,**必须有"为什么推荐"** |

### 5.2 搜索 5 要素

```markdown
## 搜索引擎
- 索引范围: 全量 / 限用户可见
- 排序: 文本相关度 → 时效 → 个性化
- 同义词: 全局表 + 域内表
- 高亮: 必须原词 + 同义词都高亮
- 0 结果: 必给"猜你想找 + 热门"

## 失败兜底
- 拼写: "你是不是想找 X?"
- 范围: "扩大搜索范围"
- 时间: "近 7 天 / 30 天 / 全部"
```

## 6. 元数据 (Meta)

```markdown
## 必填 (系统自动)
- 创建时间 / 修改时间 / 创建者
- 状态枚举 / 软删标记

## 推荐 (用户可填)
- 标签 / 描述 / 封面图
- 关联对象

## 不可见 (系统用, 不上 UI)
- 搜索引擎关键字 / 自定义字段
```

**判据**: 必填不应超过 7 项,否则用户完成率暴跌。

## 7. IA 演化规则 (IA Linting)

### 7.1 添加

- [ ] 新节点是否有 ≥10 个对象会落入? 否则并入相邻
- [ ] 是否破坏了 L0 ≤ 7 的天花板?
- [ ] 是否与既有节点存在概念重叠?

### 7.2 合并

- [ ] 两节点重叠 ≥ 50% 对象?
- [ ] 用户搜索"X"在前 5 结果中分散在两节点?

### 7.3 删除

- [ ] 节点为空超过 90 天?
- [ ] 流量 < 全站 0.1%?
- [ ] 删除前必发 301 重定向到新位置

- [ ] 每个核心对象 ≥ 3 个入口
- [ ] 同义词表覆盖搜索热词

## 9. 已知缺口 (Known Gaps)

| 缺口 | 影响 | 补足方式 |
|---|---|---|
| 真实流量未采样 | L0 选择无证据 | 上线 2 周后用埋点回填 |
| 同义词表来自"猜" | 搜索长尾词覆盖差 | 爬 query log + 编辑评审 |
| 分类边界有歧义 | 用户进错节点 | 用"示例 vs 反例"实测 |
| 大规模 IA 变形规则缺 | 长尾退化 | 跨域演练 + 每季度 lint |
