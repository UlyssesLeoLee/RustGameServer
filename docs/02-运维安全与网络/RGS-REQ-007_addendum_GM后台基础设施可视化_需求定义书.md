## 1. 目的

在不新增DNS/CDN管理写路径的前提下，为GM后台补充DNS解析状态与CDN边缘节点状态的**只读可观测性**，使运维/SRE可在同一后台完成基础设施层面的故障初判，不必跳转至外部DNS/CDN服务商控制台。

## 2. 适用范围

**范围内**：DNS解析状态只读展示、CDN边缘节点状态只读展示（复用既有`DistributionBackend`暴露指标）、异常告警。

**范围外**：DNS/CDN的写路径（记录变更、CDN配置变更UI）——沿用既有DNS/CDN服务商控制台，不在GM后台重复实现；plugin热插拔与app组件级更新展示——已由§0确认的既有文档覆盖，不在本文档重复定义。

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-OPS-005 | GM后台**必须**提供DNS解析状态只读API：对既定域名集合做多地理位置探测，展示当前解析结果与既往基线的差异；探测节奏复用FR-OPS-001既有轮询机制 |
| FR-OPS-006 | GM后台**必须**提供CDN边缘节点状态只读API：数据源为既有`DistributionBackend`已暴露的指标（复用NFR-CDN-101/102定义的边缘命中率、回源成功率），**不得**新增独立的CDN指标采集SDK |
| FR-OPS-007 | DNS解析异常（与基线不一致）或CDN边缘异常（命中率/回源成功率低于NFR-CDN-101/102阈值）**应当**复用既有FR-GM-004告警通道推送，不新增独立告警链路 |

## 4. 非功能需求

| ID | 需求 |
|---|---|
| NFR-OPS-009 | DNS/CDN探测间隔**不得**超过5分钟 |
| NFR-OPS-010 | 探测流量**必须**与生产玩家流量隔离，不得影响生产路径性能 |
| NFR-OPS-011 | 本节新增API**必须**纳入RBAC，默认仅SRE/运维角色可见（沿用ARC-019控制平面统一入口原则） |

| ID | 验收标准 |
|---|---|

| AC-OPS-008 | RBAC验证：非SRE/运维角色访问DNS/CDN状态API返回权限拒绝 |
