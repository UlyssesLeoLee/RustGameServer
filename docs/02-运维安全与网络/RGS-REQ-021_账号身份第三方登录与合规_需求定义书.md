# 1. 前言

## 1.1 目的与范围边界

RGS-REQ-001 BR-001（账号生命周期管理）自基准文档制定起仅为"注册、登录、封禁、注销、多设备控制"一行摘要，对应的FR-GW-002（鉴权・令牌验证）只处理"登录令牌的验证与会话建立"，从未回答"这个令牌最初是如何签发的"——即客户端使用何种凭证完成首次登录。本文档补齐两类此前完全空白的能力：

1. **第三方登录与跨平台账号绑定**：Apple／Google／Steam等第三方身份提供方（IdP）登录、游客账号转正式账号、多个第三方身份绑定至同一游戏账号、解绑
2. **实名认证与未成年人保护**：real-name verification、年龄核验、未成年人时长限制——若目标发行地区法规要求（与既有ISS-004"适用个人信息保护法规"联动），这是强制合规项而非可选功能

## 1.2 判定原则（先声明，避免与既有模块混淆）

- 本文档**不涉及**游戏内会话建立后的鉴权机制（既有FR-GW-002/ARC-006/RGS-BAS-001§4.1已覆盖），只处理"游戏账号最初如何被证明是这个人"这一更早的环节
- 第三方IdP的**凭证校验权威**在第三方（本系统不存储/校验第三方密码），本系统只信任第三方IdP签发的、经服务器侧验证签名的身份令牌（同ARC-005服务器权威原则的延伸：不信任客户端自证的第三方身份，必须服务器侧向IdP验证）
- 实名认证与未成年人保护的**具体规则因地区法规而异**，本文档定义的是**规则可插拔的框架**，不硬编码任何特定地区的具体规则（如是否需要人脸识别、时长上限数值），具体规则留待TBD-IDN-001按目标发行地区评审

# 2. 术语约定

| 术语 | 定义 |
|---|---|
| 身份提供方（IdP） | 第三方登录服务，如Apple／Google／Steam，负责验证用户真实身份并签发身份令牌 |
| 账号联合（Account Federation） | 一个游戏账号绑定多个第三方身份，任一身份均可用于登录同一账号 |
| 实名认证 | 核实玩家真实身份信息（因地区法规而异，未必要求，见TBD-IDN-001） |

# 3. 背景与课题

| 课题编号 | 课题 |
|---|---|
| P-IDN-001 | 游客账号缺少转正式账号（绑定第三方身份）的路径，一旦更换设备/清除数据即永久丢失游戏进度，是常见的玩家流失原因 |
| P-IDN-002 | 若第三方身份令牌的校验完全信任客户端转发而不做服务器侧向IdP验证，攻击者可伪造身份令牌冒充任意账号登录 |
| P-IDN-003 | 未成年人保护规则若硬编码为单一地区标准，无法适配多地区发行；若完全不设计，面向部分地区发行时构成合规违规 |
| P-IDN-004 | 多个第三方身份绑定同一账号后，若无明确的"解绑""合并冲突"处理规则，容易出现账号被盗后的恢复纠纷，最终都会涌向客服工单（RGS-REQ-019） |

| 业务需求 | 业务需求名 | 描述 | 优先级 |
|---|---|---|---|
| BR-IDN-001 | 玩家可用第三方账号登录 | 支持主流IdP登录，无需额外注册游戏专属密码 | 高 |

| BR-IDN-004 | 合规地区的未成年人保护 | 面向要求地区，未成年人账号的游玩时长与内容受限 | 高（视发行地区） |

# 5. 功能需求：第三方登录与账号绑定

| 编号 | 需求 |
|---|---|
| FR-IDN-001 | 系统**必须**支持至少一种第三方IdP登录（具体清单见TBD-IDN-002），登录流程**必须**在服务器侧向对应IdP验证身份令牌的签名与有效期，**不得**仅信任客户端上报的身份声明 |
| FR-IDN-002 | 系统**必须**支持游客账号（无需第三方身份即可开始游玩），游客账号的进度**必须**与正式账号使用同一套数据模型，**不得**是隔离的临时存储 |
| FR-IDN-003 | 游客账号**必须**能绑定一个或多个第三方身份完成"转正"，转正过程**不得**丢失已有进度，**不得**要求重新开始 |
| FR-IDN-004 | 一个游戏账号**必须**能同时绑定多个不同的第三方身份（如同时绑定Apple与Google），任一已绑定身份均可用于登录同一账号 |
| FR-IDN-005 | 玩家**必须**能自助解绑已绑定的第三方身份，解绑**必须**校验"解绑后账号仍至少保留一种可登录方式"（**不得**允许解绑至无法登录的状态，除非账号仍保有游客登录能力） |
| FR-IDN-006 | 若第三方身份此前已绑定其他游戏账号，尝试绑定至新账号时**必须**明确拒绝并提示冲突，**不得**静默覆盖或合并两个账号的数据 |
| FR-IDN-007 | 账号绑定/解绑操作**必须**留痕（复用RGS-BAS-003§7审计设计），作为账号被盗申诉的调查依据 |

# 6. 功能需求：实名认证与未成年人保护

| 编号 | 需求 |
|---|---|
| FR-IDN-010 | 实名认证与未成年人保护规则**必须**设计为可插拔框架：是否启用、具体验证方式（如身份证号校验、人脸识别）、未成年人时长限制数值，**均以配置驱动**（复用ARC-016热更新机制），**不得**硬编码单一地区标准 |
| FR-IDN-011 | 若目标发行地区启用实名认证（TBD-IDN-001决议范围），未完成认证的账号**必须**被限制于配置定义的功能子集（如禁止付费），具体限制范围由配置定义 |
| FR-IDN-012 | 若启用未成年人时长限制，系统**必须**基于认证得到的年龄信息对相应账号的在线时长做限制与提醒，限制逻辑**必须**在服务器侧强制执行（**不得**仅依赖客户端自律） |
| FR-IDN-013 | 实名认证信息**必须**加密存储（复用既有NFR-SE-012个人信息保护标准），访问权限**必须**独立评审，**不得**与游戏日常运营查询权限混同 |
| FR-IDN-014 | 未成年人保护相关限制的触发与解除**必须**留痕（复用RGS-BAS-003§7），供合规审计使用 |

# 8. 架构设计方针 ARC-036

## 8.1 ARC-036：身份联合边界与合规判定的单一裁决点（重要决定）

| 项目 | 内容 |
|---|---|
| **决定** | ①第三方身份的真实性**必须**由服务器侧向IdP发起验证，**不得**信任客户端自证②同一游戏账号可联合多个第三方身份，但**不允许**跨账号静默合并——绑定冲突必须显式拒绝③实名认证与未成年人保护规则**必须**通过配置驱动实现地区差异化，判定逻辑**集中**在单一的合规校验组件，**不得**分散到各业务服务各自实现（避免规则不一致） |
| **理由** | ①与ARC-005服务器权威原则一致，身份真实性不能由不可信的客户端环节担保②账号合并涉及两份独立的游戏资产/进度数据，静默合并会产生资产来源不可追溯的问题，显式拒绝+客服工单人工处理是更安全的默认行为③规则分散实现是常见的合规隐患来源——同一发行地区的两个业务服务若各自实现年龄判定逻辑，容易产生标准不一致，进而被认定为合规违规 |
| **与ARC-018的关系** | 身份联合与合规判定组件**依附**既有RT/GW/AD限界上下文运行，**不新建**独立限界上下文 |

# 9. 验收标准

| 编号 | 内容 |
|---|---|
| AC-IDN-001 | 第三方登录令牌伪造攻击测试：使用未经IdP签发的伪造令牌尝试登录，验证被拒绝 |
| AC-IDN-002 | 游客转正流程验证：游客账号绑定第三方身份后，既有进度完整保留 |
| AC-IDN-003 | 账号绑定冲突验证：已绑定账号A的第三方身份尝试绑定账号B，验证被拒绝且不产生数据合并 |
| AC-IDN-004 | 未成年人时长限制验证（若地区规则启用）：模拟未成年人账号超时长游玩，验证服务器侧强制限制生效 |
