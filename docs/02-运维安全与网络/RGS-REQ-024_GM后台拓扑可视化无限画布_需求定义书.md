# 1. 前言

## 1.1 目的

本系统当前的可观测性（RGS-REQ-008/BAS-004）以指标/日志/追踪三支柱呈现，GM后台（RGS-REQ-007/BAS-003）以表单/列表呈现管控操作与查询结果——两者都不回答一个此前从未被满足的诉求：**"整个系统当前长什么样、数据和控制正在如何流动"**这一空间性、拓扑性的整体认知。本文档新增一项GM后台能力：**无限画布**——以节点-边图的形式呈现全系统的App、组件、LangGraph分析图节点，以及它们之间此刻正在发生的数据流与控制流，并支持按颗粒度（方法级／插件级／App级）与职能视角（业务视图）切换呈现内容。

## 1.2 判定原则（先声明，避免与既有模块混淆）

- 本文档**不新建**数据采集路径。画布呈现的全部内容**必须**来自既有数据源的**读取聚合**：可观测性数据（RGS-BAS-004指标/追踪）、挂载记录（RGS-BAS-002§10 Mount Record）、插件注册表（RGS-BAS-005§3）、智能层分析图治理表（RGS-BAS-011§5A `AnalysisGraphDefinition`）。画布是这些既有数据的**新呈现方式**，不是新的真相来源
- 画布查询**不得**对生产热路径产生反向压力，复用ARC-035"分析类查询与运维查询物理隔离"的既定精神——画布数据源须走既有的读优化路径（可观测性存储/分析管线），**不得**直接高频轮询业务数据库或生产事务路径
- "动态"（实时/近实时）**不等于**"同步于生产tick"，画布的刷新时延**允许**滞后（同ARC-031"派生视图可容忍滞后"的同类思想），换取不干扰生产路径这一更高优先级的约束

## 1.3 关联文档

| 文档 | 关系 |
|---|---|
| RGS-REQ-007／BAS-003 | GM后台既有控制平面，本文档新增的画布是其新增页面/能力，复用既有RBAC与统一入口 |
| RGS-REQ-008／BAS-004 | 可观测性数据源（指标/追踪），画布的"方法级"颗粒度直接复用其Span数据 |
| RGS-REQ-006／BAS-002 | 功能挂载架构，画布的"App级"颗粒度复用其Mount Record |
| RGS-REQ-009／BAS-005 | 插件热插拔，画布的"插件级"颗粒度复用其插件注册表 |

# 2. 术语约定

| 术语 | 定义 |
|---|---|
| 无限画布（Infinite Canvas） | 可自由缩放/平移、无预设边界的节点-边图形交互界面 |
| 颗粒度（Granularity） | 画布呈现内容的抽象层级：方法级（单个RPC/函数调用）／插件级（单个插件实例）／App级（单个限界上下文/Atomic App） |
| 业务视图（Business View） | 针对特定职能角色预设的节点/边过滤与着色方案，呈现同一份底层拓扑数据的不同侧面 |

# 3. 背景与课题

| 课题编号 | 课题 |
|---|---|
| P-VIZ-001 | 系统已扩展至19个领域、约40+个功能场景，新成员与跨领域协作者缺少一种直观、空间化的方式理解"App之间如何依赖、数据如何流动"，只能通过阅读文档逐条拼凑心智模型 |
| P-VIZ-002 | 智能层（RGS-REQ-014）新增后，LangGraph分析图的节点/边结构（此前仅以文字表格描述，见RGS-BAS-011§5）缺少可视化呈现，增加了理解与审查确定性闸门覆盖范围（RGS-BAS-011§7A）的难度 |
| P-VIZ-003 | 不同职能负责人（架构师、SRE、安全负责人、经济策划、智能层负责人）对"系统长什么样"的关注点截然不同，若只有一种统一呈现，要么过于笼统无法支撑具体决策，要么过于细节让非该领域人员难以使用 |
| P-VIZ-004 | 若可视化查询直接高频访问生产数据库或热路径指标，可能重演RGS-BAS-017 ARC-035指出的"分析类大范围查询干扰运维低延迟查询"同类风险，只是这次干扰对象换成了生产业务路径本身 |

# 5. 功能需求：画布与颗粒度

| 编号 | 需求 |
|---|---|
| FR-VIZ-001 | GM后台**必须**新增无限画布页面，支持自由缩放/平移，**不得**有预设的画布边界（"无限"的体验要求，具体实现可采用视口内按需渲染，不要求真的无限存储） |
| FR-VIZ-002 | 画布**必须**支持三级颗粒度切换：**App级**（节点＝限界上下文/Atomic App，数据源为Mount Record，边＝App间的gRPC/事件依赖关系）、**插件级**（节点＝插件实例，数据源为插件注册表，边＝插件与其依附App的关系＋插件间若存在的依赖）、**方法级**（节点＝具体RPC方法/函数，数据源为既有分布式追踪Span，边＝调用关系） |
| FR-VIZ-003 | 颗粒度切换**必须**保持画布的相对位置感（如从App级下钻到该App的插件级视图时，画布焦点**应当**平滑过渡至该App对应区域），**不得**每次切换颗粒度都重置视角 |
| FR-VIZ-004 | 方法级颗粒度的数据**必须**复用既有RGS-BAS-004分布式追踪Span数据，**不得**为画布新增专属的方法级埋点采集路径 |
| FR-VIZ-005 | 画布**必须**支持节点搜索与定位（按App名/插件名/方法名/LangGraph节点名），**不得**要求用户仅靠平移缩放查找目标节点 |

# 6. 功能需求：数据流/控制流与LangGraph可视化

| 编号 | 需求 |
|---|---|
| FR-VIZ-010 | 画布**必须**呈现App/插件/方法之间的**控制流**（同步调用关系，如gRPC调用）与**数据流**（异步关系，如事件发布/订阅、Outbox分发）两类边，且**必须**以不同的视觉样式（如线型/颜色）区分二者，避免混淆同步依赖与异步依赖 |
| FR-VIZ-011 | 画布**必须**能呈现LangGraph分析图的节点与边（复用RGS-BAS-011§5A`AnalysisGraphDefinition`/`graph_spec_ref`数据），节点**应当**标注其所属`feature_domain`（RGS-BAS-011§5A.3初始功能场景目录）与确定性分级（L4，同RGS-BAS-011§7A.1） |
| FR-VIZ-012 | LangGraph可视化**必须**能叠加呈现确定性闸门（RGS-BAS-011§7A.2）的位置——即建议从智能层（L4）流向`AdminService`（L0/L1）的边**必须**在画布上被明确标注为"经过闸门"，**不得**让画布呈现出"智能层直接连接到L0/L1业务节点"这类误导性拓扑（画布本身也不得违反ARC-030"L4不得出现在L0/L1同步调用链"这一事实的准确呈现） |
| FR-VIZ-013 | 数据流/控制流边的"动态"呈现（如流量粗细、活跃度高亮）**必须**基于既有可观测性指标（RGS-BAS-004黄金指标）聚合，刷新周期**允许**滞后（NFR-VIZ-002），**不得**要求逐请求实时推送每一次调用 |
| FR-VIZ-014 | 画布**必须**能筛选/高亮"当前存在异常"的节点或边（如错误率超阈值、延迟超阈值），复用既有RGS-BAS-004黄金指标阈值定义，**不得**为画布另定一套异常判定标准 |

# 7. 功能需求：业务视图

| 编号 | 需求 |
|---|---|
| FR-VIZ-020 | 画布**必须**提供至少以下预设业务视图，每种视图为同一份底层拓扑数据的不同节点/边过滤与着色方案：①**架构总览视图**（面向架构师，App级为主，突出限界上下文边界与ARC-018挂载关系）②**运维健康视图**（面向SRE，叠加FR-VIZ-014异常高亮，突出告警中的节点）③**安全边界视图**（面向安全负责人，突出NetworkPolicy允许的边，复用RGS-BAS-006既有策略数据，**不允许**的调用路径若在追踪数据中出现须高亮为异常）④**经济流视图**（面向经济/数值策划，突出货币/道具类数据流路径，如EC限界上下文相关的边）⑤**智能层治理视图**（面向智能层负责人/安全负责人，聚焦FR-VIZ-011/012的LangGraph可视化） |

| FR-VIZ-022 | 新增业务视图（超出FR-VIZ-020既定五种）**应当**遵循可配置的视图预设描述（过滤条件+着色规则的声明式配置），**不得**要求为每个新视图单独开发前端代码 |

# 9. 架构设计方针 ARC-039

## 9.1 ARC-039：可视化数据来源的只读边界与画布性能隔离（重要决定）

| 项目 | 内容 |
|---|---|
| **决定** | ①画布呈现的全部数据**必须**来自既有数据源的**只读聚合**（可观测性存储、Mount Record、插件注册表、智能层分析图治理表），**不得**新建专属采集路径，**不得**直接查询生产事务数据库②画布查询**必须**走读优化路径（复用ARC-035既定的分析管线/可观测性存储读端点），**不得**对生产热路径或既有运维可观测性查询产生资源竞争 |
| **理由** | ①避免重复建设——系统已有丰富的可观测性与治理数据源，画布的价值在于**呈现方式**的创新而非数据采集的重复②ARC-035已确立"分析类大范围查询与运维查询物理隔离"的教训，画布查询同属"大范围、非实时敏感"的读取模式，理应适用同一原则，否则重蹈其解决的同一类问题 |
| **与ARC-018的关系** | 画布相关组件（后端聚合服务、前端渲染）**依附**既有GM后台（AD限界上下文）运行，**不新建**独立限界上下文 |

# 10. 验收标准

| 编号 | 内容 |
|---|---|
| AC-VIZ-001 | 颗粒度切换验证：从App级下钻至某App的插件级、再下钻至某插件的方法级，画布内容与既有Mount Record/插件注册表/追踪数据一致，且下钻过程视角平滑过渡 |
| AC-VIZ-002 | LangGraph可视化验证：抽查一个已注册的分析图场景（RGS-BAS-011§5A.3），画布呈现的节点/边与其`graph_spec_ref`实际定义一致，且闸门位置标注正确 |
| AC-VIZ-003 | 业务视图验证：切换至少3种预设业务视图，验证节点/边的过滤与着色符合各自定义 |
| AC-VIZ-004 | 性能隔离验证：画布高频操作（连续缩放/平移/切换视图）期间，生产业务路径与既有运维可观测性查询的延迟无劣化（NFR-VIZ-003） |
