## 1. 背景与问题

### 1.1 当前痛点

RGS / Physis / GVPE 项目的客户端粒子特效涉及多个引擎的混合使用：

- **Unity**：内置 `ParticleSystem` + `VFX Graph`
- **Unreal Engine**：`Niagara`（UE5）/ `Cascade`（UE4 遗留）
- **Godot 4**：`GPUParticles3D` / `CPUParticles3D` / `GPUParticles2D` / `CPUParticles2D`
- **自研引擎**：Physis 物理引擎 + GVPE 视觉表现层的 C ABI 绑定（`gvpe_particle_*`）

每个引擎的粒子 API 命名、参数语义、生命周期回调完全不同，开发者需要：

1. 跨 4 个官方文档站点交叉查阅 → 切换成本高
2. 跨语言（C# / C++ / GDScript / C）反复粘贴示例 → 容易张冠李戴
3. 不确定某个 API 在 RGS 业务语境下应该用哪个引擎实现 → 选型困惑
4. 不知道某个粒子参数在物理引擎（Physis）和表现层（GVPE）之间如何联动 → 联调低效

### 1.2 目标

提供一个**常驻后台的纯前端工具页**，单一入口聚合所有引擎的粒子 API 信息，支持：

- 按引擎 / 类别两级选项卡快速定位
- 点击 API 即弹出详情卡，同一 API 在 4 个引擎下的调用示例并列对比
- 离线可访问（不依赖外部 CDN / 文档站）
- 后续可作为 RGS 客户端粒子开发的事实参考

### 1.3 非目标

- ❌ 不做粒子实时编辑器（仅展示 API 文档，不渲染粒子）
- ❌ 不做代码生成（不直接输出可编译代码片段到剪贴板以外的位置）
- ❌ 不替代各引擎官方文档站（仅做摘录 + RGS 业务语境注释）
- ❌ 不做 API 变更通知 / 自动抓取（数据源以手写 JSON 为主，辅以人工校对）

## 3. 功能需求

### 3.1 FR-PAB-001 列表展示

- **功能描述**：页面默认展示按"引擎"一级选项卡 + "类别"二级选项卡组织的 API 列表
- **入口**：打开 `index.html` 即默认进入"所有引擎 / 全部"视图
- **列表项字段**：
  - API 名称（如 `ParticleSystem.Emit` / `NiagaraComponent.SetNiagaraVariableFloat` / `GPUParticles3D.emitting` / `gvpe_particle_emit`）
  - 所属引擎徽标（UE / Unity / Godot / Physis）
  - 简短一句话描述
  - 标签（如 `Emit` / `Color` / `Force` / `Lifecycle`）
- **交互**：
  - 顶部一级选项卡：`所有引擎 | Unity | Unreal | Godot | Physis`（5 个）
  - 二级选项卡按引擎动态展示类别（见 §3.2）
  - 列表项支持键盘上下方向键导航 + Enter 打开详情
  - 搜索框（顶部右侧）：模糊匹配 API 名称 + 描述

### 3.2 FR-PAB-002 类别分类

按引擎提供预定义类别（按需求细化时**已与官方文档分类对齐**）：

| 引擎 | 二级类别 |
|------|----------|
| **Unity** | 发射 / 生命周期 / 形状 / 颜色与渐变 / 大小与旋转 / 速度与力 / 碰撞 / 子发射器 / 外部力场 |
| **Unreal** | Spawn / Update / Render / Events / GPU Sim / Material / Performance / Variable |
| **Godot 4** | 发射 / 进程 / 绘制 / 碰撞 / 子发射器 / 纹理 / 材质 |
| **Physis** | 粒子发射 / 积分器 / 碰撞 / 力场 / 生命周期 / 同步回调 |

### 3.3 FR-PAB-003 详情弹窗

- **触发**：点击列表项 / 按 Enter / 键盘快捷键（选中后按空格）
- **布局**：
  ```
  ┌─────────────────────────────────────────────────────┐
  │ [×]                                                  │
  │ API: ParticleSystem.Emit                            │
  │ 引擎: Unity  |  类别: 发射  |  标签: Emit, Burst   │
  │ ──────────────────────────────────────────────────  │
  │ [ 概述 | 参数 | 示例 | 注意事项 | 引擎差异 ]         │ ← 弹窗内一级 tab
  │                                                       │
  │ ──────────── 概述 ────────────                       │
  │ 立即发射 N 个粒子，跳过发射速率限制。                │
  │ 适用于命中特效、爆炸、伤害飘字等瞬时场景。          │
  │                                                       │
  │ ──────────── 示例（弹窗内二级 tab：引擎切换）──       │
  │ [ Unity | UE | Godot | Physis ]                      │
  │                                                       │
  │ Unity C# 示例:                                       │
  │ ┌─────────────────────────────────────────────────┐ │
  │ │ var ps = GetComponent<ParticleSystem>();         │ │
  │ │ ps.Emit(50);  // 立即发射 50 个粒子              │ │
  │ └─────────────────────────────────────────────────┘ │
  └─────────────────────────────────────────────────────┘
  ```
- **弹窗内一级 tab**：`概述 | 参数 | 示例 | 注意事项 | 引擎差异`（5 个）
- **弹窗内二级 tab**（在"示例"tab 内）：`Unity | Unreal | Godot | Physis`（4 个，按用户多选展示——本工具默认全开）
- **代码块**：等宽字体 + 引擎对应的语法高亮配色（轻量级正则着色，不引入完整 highlighter）
- **关闭**：右上角 × / Esc / 点击遮罩外

### 3.4 FR-PAB-004 多引擎示例对比

- **需求来源**：用户在原始需求中明确要求"各个主流引擎的粒子都写上"
- **覆盖范围**：每个 API 在 `api.json` 中应至少包含以下示例字段（缺一即视为数据不全，UI 标"暂无示例"提示）：
  - `examples.unity`（C#）
  - `examples.unreal`（C++ / BluePrint 伪代码二选一）
  - `examples.godot`（GDScript 4.x）
  - `examples.physis`（C，调用 `gvpe_particle_*` C ABI）
- **示例质量标准**：
  - 可编译 / 可运行（不写伪代码）
  - 包含最小上下文（变量声明 + 调用 + 注释）
  - 注释用中文，标注该示例在 RGS 项目中的典型用途

### 3.5 FR-PAB-005 引擎差异提示

- 在详情弹窗的"引擎差异"tab 中，按"Unity / Unreal / Godot / Physis"列出同一概念的语义差异
- 用途：避免开发者将一个引擎的直觉套用到另一个引擎
- 示例条目（API: `Emit` / `emitting` / `Trigger` / `gvpe_particle_emit`）：
  | 引擎 | 行为 | 备注 |
  |------|------|------|
  | Unity `ParticleSystem.Emit(count)` | 同步立即发射，跳过 `emission.rateOverTime` | 仅对 CPU 模拟生效；GPU 模拟下退化为延迟发射 |
  | UE `UNiagaraComponent::Activate(bool bReset)` | 启动或重置发射 | 默认持续发射，需配合 `Deactivate()` 停止 |
  | Godot `GPUParticles3D.emitting = true` | 切换布尔值控制发射 | 立即生效，无中间态 |
  | Physis `gvpe_particle_emit(handle, n)` | 同步发射到物理世界 | 与 GVPE 表现层通过 `gvpe_visual_attach()` 联动 |

### 3.6 FR-PAB-006 搜索 / 过滤

- **搜索框位置**：页面顶部固定
- **搜索维度**：
  1. API 名称（精确 / 前缀匹配优先）
  2. 描述文本（分词模糊匹配）
  3. 标签（精确匹配）
- **搜索结果**：在当前选项卡范围内过滤；切换选项卡时搜索词保留
- **快捷键**：`/` 聚焦搜索框，`Esc` 退出

### 3.7 FR-PAB-007 数据可维护性

- **数据文件**：所有 API 信息存储在 `data/api.json`（UTF-8，无 BOM）
- **数据格式**：见详细设计书 §3
- **添加新 API**：直接编辑 `api.json`，无需重新构建
- **校验**：页面加载时若 JSON 解析失败，顶部红色横幅提示"数据加载失败"并展示原始错误

### 3.8 FR-PAB-008 离线 / 后台运行

- **目标**：浏览器打开 `index.html` 即可使用，无后端依赖
- **部署方式**：
  - 直接双击 `index.html`（`file://` 协议下 JSON 加载需 `fetch`，部分浏览器禁止；详见基本设计书 §4.3）
  - 通过 `python -m http.server` / `npx http-server` / `tools/rgs-web/server.js` 提供 HTTP 服务（推荐）
- **无外部依赖**：CDN 字体 / 外部 JS 库 / 远程图片一律不引入
- **可选**：支持 `tools/rgs-web/server.js` 反代同目录静态资源（与现有 `rgs-web` 工具同进程）

## 4. 非功能需求

### 4.1 NFR-PAB-001 性能

- 首屏加载 < 500ms（`api.json` ≤ 200KB 假设下）
- 列表渲染 < 16ms / 1000 项
- 选项卡切换 < 50ms

### 4.2 NFR-PAB-002 兼容性

- 浏览器：Chrome 100+ / Edge 100+ / Firefox 100+ / Safari 15+
- 屏幕：1280×720 起，主流桌面分辨率；移动端不强求（但布局不应崩）

### 4.3 NFR-PAB-003 可访问性（A11y）

- 所有交互可纯键盘完成
- 选项卡 `role="tab"` + `aria-selected`
- 弹窗 `role="dialog"` + `aria-modal="true"` + 焦点陷阱
- 颜色对比度 ≥ 4.5:1（WCAG AA）

### 4.4 NFR-PAB-004 视觉风格

- 默认深色主题（开发者工具惯例）
- 配色：背景 `#0d1117`，前景 `#e6edf3`，强调色 `#58a6ff`，次强调 `#f78166`
- 代码块：背景 `#161b22`，边框 `#30363d`
- 字体：系统等宽栈（`Consolas, "Cascadia Mono", "JetBrains Mono", monospace`）

### 4.5 NFR-PAB-005 可扩展性

- 新增引擎：仅需在 `api.json` 中增加 `examples.<engine>` 字段，UI 自动渲染
- 新增类别：编辑 `data/categories.json`
- 国际化：所有 UI 文案集中在 `data/i18n.json`（v0.1 仅中文，预留 key）

### 4.6 NFR-PAB-006 安全

- 不发起任何外部网络请求
- 不使用 `eval` / `Function` 动态执行
- 不写入 `localStorage` / `cookie`（避免在 `file://` 协议下抛错）
- 代码块不渲染为 HTML（用 `textContent` 而非 `innerHTML`），杜绝 XSS

## 6. 数据规模初判

- 计划覆盖 4 引擎 × 平均 6 类别 × 每类别 5-10 API ≈ **120-240 个 API**
- 单条 API 约 2-5KB JSON → 总数据 **240KB-1.2MB**（gzip 后 < 400KB）
- v0.1 先录入 8-12 条真实 API 作为骨架验证
